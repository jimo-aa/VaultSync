# VaultSync 核心引擎设计

> 文档编号：02 ｜ 版本：V0.2 ｜ 定位：**设计文档（不含源码）**
> 深度：框架级 + 关键流程

---

## 一、引擎定位与目标

核心引擎（下文统一称 **Engine**）是由 **Rust** 实现的原生库，通过 FFI 暴露给 Flutter 前端。它是 VaultSync 中**唯一允许接触密钥、明文与文件系统**的组件。

**设计目标：**

1. 将全部安全逻辑（密钥派生、加密、擦除、隐写、审计）下沉到原生层，前端不可触达敏感数据。
2. 提供**稳定、类型安全、异步友好**的接口契约，屏蔽语言边界细节。
3. 支持多平台（Windows / macOS / Linux / Android / iOS）单一内核。
4. 具备清晰的模块边界与可测试性，便于针对密钥与加密逻辑做独立安全测试。

**非目标：** 引擎不负责 UI 渲染、本地化与平台弹窗；这些由前端负责。

## 二、引擎运行时模型

### 2.1 进程与线程模型

Engine 以全局单例方式初始化，运行在独立线程池（`std::sync` + 工作线程池）中：

```
                     ┌─────────────────────────────┐
 UI 事件 / 后台任务   │         Engine(Singleton)    │
     │               │  ┌──────────────┐  ┌──────┐ │
     ├──FFI─────────▶│  │ 会话管理      │  │工作池 │ │
     │ (合同/回调)     │  └──────────────┘  └──────┘ │
     │               │   │ 派发到 worker               │
     │               │  ┌──────┐ ┌──────┐ ┌──────┐    │
     └──事件流◀──────│  │加密   │ │同步  │ │隐写  │    │
                    │  │worker│ │worker│ │worker│    │
                    │  └──────┘ └──────┘ └──────┘    │
                    └─────────────────────────────┘
```

- **串行化密钥访问**：所有涉及密钥的调用统一收敛到 `vault-crypto` 的临界区，避免并发竞争与密钥错用。
- **长任务可中断/可取消**：同步、加密等长任务支持取消令牌，前端可据此实现"取消"操作。

### 2.2 会话（Session）模型

- Engine 使用**会话令牌（Session Token）**标识一次解锁后的会话。
- 解锁时由 Engine 派生并持有主相关密钥，生成会话令牌回传前端；前端所有安全调用都携带该令牌。
- 锁定时，Engine 主动回收并 **Zeroize** 内存中的密钥副本，使后续调用因令牌失效而被拒绝。

会话生命周期流程：主密码 / 生物识别 → Engine 解锁 →（成功后）持有密钥并签发会话令牌 → 前端携带令牌往返调用安全 API →（空闲 / 锁屏 / 手动触发锁定）Zeroize 密钥，会话令牌失效。

## 三、模块划分与职责

Engine 采用 Rust Workspace，分六大 crate。内部依赖单向、无环。

### 3.1 `vault-core`（门面与编排）

- **唯一 FFI 门面**：导出 C ABI 入口，统一线程调度、任务派发与错误上报。
- 维护引擎生命周期：`engine_init` / `engine_unlock` / `engine_lock` / `engine_shutdown`。
- 负责把工程师关注点（会话、任务队列、进度回调）向上层暴露为稳定契约。

### 3.2 `vault-crypto`（密码原语库）

提供所有密码学原语，**不感知业务对象**：

| 能力 | 用途 | 安全性要求 |
| --- | --- | --- |
| Argon2id | 主密码 → KEK_pwd（密码包装钥匙）派生 | 参数化（内存 / 迭代 / 并行度），按平台分级 |
| HKDF-SHA256 | MK → 文件夹子密钥、验证器派生 | 单向、盐化 |
| AES-256-GCM | 块级加密（AEAD） | nonce = 每文件随机前缀(32bit) + 块计数器(64bit)，**禁止同一 FSKey 下随机 nonce** |
| Noise 协议 | P2P 传输层加密 | 传输握手与加密 |
| HMAC-SHA256 | 信令完整性与防重放 | 抗篡改 |
| Zeroize | 密钥与明文内存擦除 | 调用后内存不可残留 |
| 安全随机数 | MK / FSKey / nonce 前缀 / salt | CSPRNG |
| FastCDC（Rabin 滚动哈希） | 内容定义分块，加密=同步=传输块 | 平均块 64KB–256KB 自适应 |

### 3.3 `vault-vault`（保险箱域）

承载 V0.1 中的"加密文件保险箱"：三层密钥、文件加解密、安全擦除、分类 / 标签 / 索引、缩略图缓存。

### 3.4 `vault-p2p`（P2P 与同步域）

承载"设备配对与同步"与"端到端加密通信"：libp2p 网络栈、设备发现 / 配对、增量同步（rsync 式分块）、断点续传、冲突解决、选择性同步、阅后即焚传输。

### 3.5 `vault-stego`（隐写域）

承载"隐写术引擎"：LSB 嵌入 / 提取、图片编解码、文件分割多图。默认处于"未启用"状态，由安全中心开关控制。

### 3.6 `vault-audit`（审计域）

承载"安全中心"的审计日志：链式哈希、事件上报、导出、完整性校验。

### 3.7 模块依赖矩阵

| 依赖 ↓ 被依赖 → | core | crypto | vault | p2p | stego | audit |
| --- | --- | --- | --- | --- | --- | --- |
| core | — | ✔ | ✔ | ✔ | ✔ | ✔ |
| crypto | — | — | ✔ | ✔ | ✔ | — |
| vault | — | — | — | — | — | ✔ |
| p2p | — | — | — | — | — | ✔ |
| stego | — | — | — | — | — | — |
| audit | — | — | — | — | — | — |

> 不存在循环；`crypto` 是最底层依赖；`audit` 被上层反向引用做事件上报。

## 四、关键流程设计

### 4.1 初次初始化与主密码设置流程

1. 前端调用 `vault-core`：初始化（init），引擎载入配置并执行测试自检；
2. 前端设置主密码（口令）；
3. `vault-core` 调用 `vault-crypto`：CSPRNG 生成主密钥 MK（仅存内存）；以 Argon2id 从主密码派生 KEK_pwd；
4. 生成 MK 的 wrapped 副本（KEK_pwd 包装）与独立验证器（MK 经 HKDF 派生，不暴露 MK）；
5. wrapped 副本 + KDF 参数 + salt 写入保险箱头部文件；生物识别绑定后追加 KEK_bio 包装的第二副本（见 `05-01`）；
6. Zeroize MK、KEK 的内存副本；
7. 向前端返回结果（不返回任何密钥）。

### 4.2 解锁（含生物识别/主密码）流程

- **主密码解锁**：前端提交密码 → `vault-crypto` 以 Argon2id 派生候选 KEK_pwd → 解封 MK wrapped 副本 → 验证器比对 → 成功后向前端签发会话令牌；
- **生物识别解锁**：前端先完成 OS 生物识别认证（无密码）→ 持安全区句柄请求解锁 → 引擎经平台安全区解封 KEK_bio → 解封 MK wrapped 副本 → 验证器比对 → 签发会话令牌；安全区不可用时自动降级主密码路径；
- **失败**：返回失败结果 → 触发锁定延时与暴力破解计数（联动安全中心）。

### 4.3 导入文件（保险箱写入）流程

1. 前端选择文件 → 调用 `vault_import(会话, 源路径, 目标文件夹, 选项)`。
2. Engine 流式读取 → 使用该文件夹子密钥派生后的文件级会话密钥加密（分块 GCM）。
3. 写入保险箱存储（保留加密文件名与元数据）。
4. 登记索引 / 缩略图（可选）→ 写审计日志 → 触发同步预排程。
5. 全程峰值内存恒定（流式）。

### 4.4 P2P 增量同步流程

文件变化事件 → CDC 内容定义分块（加密块 = 同步块 = 传输块）→ 逐块计算强哈希（SHA-256）→ 发送方向对端发送哈希列表 → 接收方与本地比对识别差异块 → 仅传输差异块 / 新块 → 接收方逐块 GCM 校验后重组文件并校验最终哈希 → 写审计日志 / 更新向量时钟。

### 4.5 安全擦除流程

删除指令 → 多次覆写磁盘扇区 → Zeroize 内存副本 → 调用平台安全删除 API → 经 P2P 传播删除到所有对端 → 写审计日志。

## 五、FFI 接口契约（规范，非源码）

> 本节只定义接口**签名契约与约定**，不含实现代码。实际代码见 `05-0X` 模块文档。

### 5.1 通用约定

- **命名**：`vs_<动作>`（如 `vs_unlock`），返回统一 `VsResult`。
- **句柄**：会话为不透明句柄（`opaque`），前端不解析其内部。
- **数据交换**：跨 FFI 传输密文块/二进制时，使用由 Engine 分配、前端负责释放的缓冲（所有权显式说明）。
- **错误**：统一错误码表 `vs_err_e`，跨 FFI 传输 `err_code + err_msg`。
- **回调**：进度与事件通过回调/事件流（双向通道）上报，前端注册 Listener。

### 5.2 主要契约清单（概览）

| 领域 | 契约（示意） | 说明 |
| --- | --- | --- |
| 生命周期 | `vs_init / vs_shutdown` | 单例初始化与销毁 |
| 会话 | `vs_unlock / vs_lock / vs_unlock_biometric` | 解锁可带密码或生物句柄 |
| 保险箱 | `vs_vault_import / vs_vault_export / vs_vault_delete / vs_vault_list` | 文件操作（流式回调进度） |
| 密钥派生 | `vs_vault_rewrap`（改密码 / 生物识别重绑定时重包装 MK） | 前端不可请求派生任意密钥；派生全部为引擎内部行为 |
| 安全擦除 | `vs_wipe_file / vs_wipe_memory` | 加密擦除（销毁密钥）+ 按介质适配的覆写 |
| P2P | `vs_p2p_pair / vs_p2p_discover / vs_p2p_sync / vs_p2p_resume / vs_p2p_conflict_resolve` | 配对 / 发现 / 同步 / 续传 / 冲突 |
| 隐写 | `vs_stego_embed / vs_stego_extract / vs_stego_enable` | 隐写（默认禁用） |
| 审计 | `vs_audit_read / vs_audit_export / vs_audit_verify` | 审计读取 / 导出 / 校验 |
| 紧急 | `vs_emergency_wipe / vs_emergency_remote_wipe` | 本地 / 远程 / 联动销毁 |

### 5.3 版本化

- FFI 契约使用**语义化版本**；破坏性变更抬升主版本并要求前端同步升级。
- 提供 `vs_abi_version` 供两端在初始化时握手校验，防止二进制不匹配。

## 六、安全边界与非功能性目标

| 类别 | 目标与约束 |
| --- | --- |
| 密钥常驻 | 仅在解锁期间于引擎进程内存存活，锁定时 Zeroize |
| 明文留存 | 除摩擦缓冲外不长期缓存明文；处理后即刻清零 |
| 大文件 | 流式加解密，峰值内存与文件大小无关 |
| 并发 | **控制面收敛、数据面并行**：密钥访问统一收敛到 `vault-crypto` 临界区；文件级加解密 / 同步任务在线程池完全并行（AES-NI 加速，Windows IOCP / Linux io_uring 异步 IO） |
| FFI 效率 | 缓冲区按 SIMD 要求对齐；高频进度事件在引擎侧合并后批量上报，避免打穿 Dart 事件循环 |
| 可观察 | 事件流上报进度、事件；审计日志落库 |
| 可恢复 | FFI 调用的幂等/可重入语义，支持断点续传恢复 |

## 七、测试与验证策略（引擎）

- **密码学向量测试**：对 Argon2id / GCM / HKDF 使用官方测试向量断言。
- **属性测试**：加解密往返、分块重组一致性。
- **模糊测试**：对 FFI 入口输入非法参数/截断数据，验证不崩溃、不泄露。
- **内存检查**：运行时验证 Zeroize 后缓冲区无残留。
- **并发测试**：多线程并发调用同一会话的安全 API，验证无竞争。
