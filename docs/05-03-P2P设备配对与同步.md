## 三、设备发现与配对

### 3.1 四种方式统一抽象

各发现 / 配对方式最终统一汇入双向认证：

- **发现**：局域网广播 mDNS；
- **配对载体**：二维码（扫码）、邀请码（一次性）、手动输入 ID + 公钥；
- **双向认证**：交换公钥 + 校验指纹 + 用户确认；
- **认证通过后**：建立长期加密信道 + 登记节点清单 + 审计。

### 3.2 双向认证关键点

- 双方交换 `public key` 与 `device_id`。
- 用户在**对端**确认配对请求（防 MITM）。
- 指纹（公钥哈希前若干字节）在双方 UI 展示核验。

## 四、P2P 传输层

### 4.1 传输路径选择

| 顺序 | 路径 | 触发 |
| --- | --- | --- |
| 1 | TCP 直连 | NAT 可穿透 |
| 2 | Hole-punching 直连 | 双方 NAT 后可穿透 |
| 3 | WebSocket 中继 | 直连失败（仅转发密文） |

### 4.2 加密与完整性

- 传输信道用 **Noise 协议**加密（运输层）。
- 数据块再以文件密钥加密（应用层），双保险。

## 五、增量同步设计

### 5.1 CDC 内容定义分块

同步交互时序如下（块与加密块严格对齐，见 `05-02` §3.2）：

1. 发送方按 CDC 分块并从加密元数据直接取块哈希列表，发送给接收方；
2. 接收方与本地块清单比对，识别相同 / 差异块；
3. 接收方回传差异块号与新块请求；
4. 发送方仅传输差异块 / 新块（块内已是密文，逐块 GCM 保护）；
5. 接收方逐块校验后重组文件，比对整文件 SHA-256，随后更新向量时钟并记审计。

```
文件 → FastCDC 块(平均64KB) → 块哈希清单(存于加密元数据)
发送哈希列表 → 接收方比对本机 → 差异块清单 → 仅传差异/新块(密文)
```

### 5.2 分块参数

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| 分块算法 | FastCDC（Rabin 滚动哈希） | 内容定义，插入不失效其后块 |
| 平均块大小 | 64KB（<1MB 文件 16KB） | 加密=同步=传输块 |
| 块上限 | 256KB | 防退化超长块 |
| 强哈希 | SHA-256 | 校验强度 |

### 5.3 首次 vs 增量

- 首次同步：全量传输。
- 后续修改：仅传输变更块。

## 六、断点续传与冲突解决

### 6.1 断点续传

- 记录已传输 `块偏移`，恢复连接后从断点继续。
- 幂等：已到块的强哈希校验通过即可复用。

### 6.2 冲突解决策略

策略按以下**固定优先级**裁决：

1. **删除优先于版本保留**：一方删除 + 一方修改 → 删除优先（安全类产品宁可误删不残留；冲突副本同样加密，仅在删除方为"误删保护窗口期"内时保留加密副本）；
2. 无删除时**保留多版本**：冲突文件生成加密时间戳副本 `doc_v1.vault` / `doc_v2.vault`；
3. **向量时钟**用于识别因果关系，减少虚假冲突（不直接裁决，仅辅助 1/2 判定）。

```dart
// 前端冲突解决示意
class ConflictService {
  Future<List<Conflict>> pending() => ffi.vs_p2p_conflicts();
  Future<void> resolveKeep(String id, String version) async {
    await ffi.vs_p2p_conflict_resolve(id, version);
  }
}
```

## 七、选择性同步设计

| 过滤维度 | 规则 | 应用场景 |
| --- | --- | --- |
| 文件夹 | 指定不作同步 | 本地临时目录 |
| 文件大小 | 超阈值需手动 | >1GB 不自动同步 |
| 网络类型 | WiFi 同步大文件 | 蜂窝仅元数据/小文件 |
| 设备 | 按目标设备过滤 | 工作文档仅到工作电脑 |

```yaml
# 同步策略配置示意
sync:
  enable: true
  window: "09:00-18:00"
  bandwidth_limit: { up: "10MB/s", down: "10MB/s" }
  wifi_only_big_file: true
  filter:
    folder_exclude: ["临时文件", "cache"]
    size_max_auto: 1073741824   # 1GB
```
