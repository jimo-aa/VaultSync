## 一、模块职责

提供"加密之上的隐蔽"：将已在引擎内加密后的文件数据，嵌入到普通图片的 **LSB（最低有效位）** 中，实现隐蔽存储与传输。攻击者即便察觉存在隐写痕迹，也无法解密出原始数据（双重保护）。

## 三、LSB 嵌入原理与容量

### 3.1 嵌入原理

- 图片 RGB 通道最低有效位对人类视觉几乎无影响。
- 加密文件数据按位写入像素 LSB。

### 3.2 容量估算

| 图片尺寸 | 容量公式 | 约容量 |
| --- | --- | --- |
| 1920×1080 | 1920 × 1080 × 3 ÷ 8 | ≈ 760 KB |
| 大文件 | 分割嵌入多张图片 | 按图片数线性扩展 |

### 3.3 加密先行

流程链路（嵌入与提取互为逆过程）：

明文文件 —（AES-256-GCM 加密）→ 密文 —（写入头 / 分割）→ 数据帧 —（LSB 按位嵌入）→ 携带隐藏数据的图片；提取时反向进行：图片 —（LSB 提取）→ 数据帧 —（AES-256-GCM 解密）→ 明文还原。

## 四、数据包格式（概念）

图片中嵌入的载荷由以下部分构成（均密文）：

| 区段 | 内容 |
| --- | --- |
| Magic + 版本 | **默认省略**（写入会自曝隐写存在）；提取端以"首个非载荷数据帧"作为同步标记，混淆模式下才可选启用 |
| Header | 原文件名、大小、被加密元数据 |
| 数据块 | 分块密文，支持跨图分割 |
| 完整性 | 最终强哈希校验 |

## 五、接口契约与示意代码

```dart
// 隐写服务（默认 disabled；启用后可用）
class StegoService {
  Future<bool> isEnabled() => ffi.vs_stego_status();
  Future<void> enable() async => ffi.vs_stego_enable(); // 需安全中心确认

  Future<StegoJob> embed(String fileId, String imagePath) async {
    return await ffi.vs_stego_embed(session, fileId, imagePath);
  }
  Future<FileId> extract(String imagePath) async =>
      await ffi.vs_stego_extract(session, imagePath);
}
```

```rust
// LSB 嵌入示意（伪代码）
fn embed_payload(img: &mut Image, cipher: &[u8]) {
    let mut bit = 0u8;
    for byte in cipher.iter() {
        for b in 0..8 {
            let p = img.pixel_bytes_mut(); // 当前像素 LSB 位置
            // 取 (byte>>b)&1 写入最低有效位
            *p = (*p & !1) | ((*byte >> b) & 1);
        }
    }
}
```

## 六、安全约束与注意事项

| 注意点 | 处理 |
| --- | --- |
| 隐写痕迹检测 | "加密先行"保证即使检测到痕迹也无法解密；可用无损图片（PNG）避免压缩破坏 LSB |
| 有损压缩（JPG） | 避免；如有必要，嵌入前转无损或采用更鲁棒方案 |
| 隐写法安全边界 | 仅作隐蔽辅助，不替代主保险箱；容量有限 |
| 启用即受审计 | 嵌入/提取均写入 `vault-audit` |
