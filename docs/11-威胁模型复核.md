## 一、复核方法与判定口径

对 `docs/06` 的每个对手级别（T1–T6）、每条安全边界声明（§四）、每项模块映射（§六）逐条给出：

| 判定 | 含义 |
| --- | --- |
| ✅ 已验证 | 有源码位置与可复现证据（测试/冒烟断言/实机观察）支撑 |
| ⚠️ 部分 | 有实现但覆盖不全，或仅在设计上成立、无运行时证据 |
| ❌ 未实现 | 文档声称而代码中不存在 |
| ⬜ 边界外 | 属 `docs/06 §五` 明示不做的范围 |

证据一律给出 `文件:行` 或测试名，**不以"设计如此"代替实现证据**。本次复核未做形式化验证与第三方审计；结论仅代表"实现与文档一致"这一层。

## 二、对手级别复核

### T1 网络窃听者 — ✅ 已验证

- 传输加密：`native/vault-p2p/src/channel.rs`（snow Noise XX / XXpsk3），握手后所有明文经 AEAD 封装；
- 双层加密：同步传输的是**已加密的容器块**（`vault-vault/src/vault.rs::read_chunk_ct`），且接收端按 GCM 逐块校验（`verify_file`）；协议演进（P4-9）后另有接收端整文件 SHA-256 终验；
- 冒烟证据：`tool/ffi_check.dart` 的「P3 同步内容长度一致」「P3 A 导出同步来的文件」；单测 `manifest_fskey_manual_decrypt`。
- ⚠️ 一处**未实现**：`docs/06 §三` 与 `docs/05-04` 提到「可选填充」以对抗长度侧信道——代码中**无填充实现**（`grep padding native/vault-p2p` 无结果）。长度与消息边界仍可被观测者推断出粗粒度信息。文档已标注"可选"，本次复核确认其**未落地**。

### T2 恶意中继 / 信令节点 — ✅ 已验证

- 中继不落盘、不解密：`native/vault-relay/src/main.rs`（136 行）中 `std::fs` / `File::` 出现 **0 次**；仅有 `VSR1 <room>` 房间配对 + 双向字节转发 + FNV 房间哈希日志；
- 信令防重放：`channel.rs` 的 `send_seq` / `recv_seq` 单调序号（`send_seq.to_be_bytes()` 编入 AAD，递增于每次发送）；
- 销毁指令带发起方长期身份签名（`docs/08 §四`）：`vault-p2p/src/engine.rs::destroy_arm_remote` 签名体 `vsync-destroy:{target}:{delay_ms}:{ts}`，接收端验签 + 目标核验；
- 冒烟证据：「P3 错误邀请码被拒」「P3 远程销毁指令已签发送达」「P3 延迟销毁到期后 B 保险箱文件被擦除」。

### T3 设备磁盘攻击者（锁定态） — ✅ 已验证

- 容器密文：`vault-vault/src/container.rs`（VSEF v2：明文头部版本化 + 加密元数据 + 逐块 AEAD）；
- 索引密文：`vault-vault/src/index.rs`（VSIX v2 整体 AEAD，密钥 `HKDF(MK,"vault-index")`）；
- MK 仅以 wrapped 形态存在：`vault-core/src/keystore.rs`（VSVB v2：`MK_wrap_pwd` / `MK_wrap_bio` + verifier），MK 由 CSPRNG 生成且永不变更；
- 抗离线爆破：Argon2id 64 MiB / t=3 / p=2（`vault-crypto/src/kdf.rs`，参数见 `docs/05-01 §3.1`）；
- 锁定态内存：`Session.mk` 为 `Zeroizing<[u8; KEY_LEN]>`（`session.rs:14`），`vault_core_lock` 直接 `Box::from_raw` 释放 → `Drop` 擦除；`vault-core` 单测断言擦除后全零（`session.rs` 测试 `mk` 全 0 断言）；
- 冒烟证据：「P1 改密码后旧密文可读（零重加密）」「P2 导出内容逐字节一致」。

### T4 物理接触解锁态设备 — ⚠️ 部分

| 缓解项 | 状态 | 证据 |
| --- | --- | --- |
| 空闲自动落锁 | ✅ | `state/session_controller.dart::notifyActivity` + `shell/home_shell.dart` 根部 `Listener`（指针/滚轮活动重置倒计时，0=关闭） |
| 伪装入口（胁迫） | ✅ | `session_controller.dart::unlock`：命中伪装密码且开关关闭时按「密码错误」处理（与错误不可区分）；伪装空间可从设置页创建（独立文件 + 独立 MK） |
| 紧急销毁 · 本机 | ✅ | FFI `vault_core_destroy_local` → `service.rs::wipe_local`（覆写 + 删除保险箱头部与整个数据目录）；冒烟「P5 销毁后保险箱头部已删除 / 数据目录已删除」 |
| 紧急销毁 · 远程 | ⚠️ | `destroy_arm_remote(addr, target, delay)` 已实现且能验签执行，但**对端地址不在对端登记表中**（`PeerRec` 只有 name/pub_hex/paired_ms/counter）——UI 无法自动投递，需人工填地址 |
| 紧急销毁 · 全设备联动 / 离线队列 | ✅（2026-09-20 补齐） | `vault-p2p/src/orders.rs`：指令签名后加密落盘、对端建连后（清单交换前）投递、**收到 ACK 才出队**；接收端验签 + 目标核验，拒绝一律不执行（含「错签名/错目标不擦除」单测与两个方向的投递集成测试） |

**结论（2026-09-20 更新）**：T4 的四项缓解均已落地。**销毁的最终一致性现已成立**：离线设备在上线后的首次信道建立时、处理任何业务消息之前收到并执行销毁指令；边界（docs/06 §四.5 已声明）仍为「永不上线设备不受保护」。

### T5 同权限恶意软件 — ⬜ 边界外（纵深缓解已做）

- `docs/06 §五` 明示超出边界。纵深缓解证据：全链路 `Zeroizing`（`vault-crypto` 的密钥缓冲、`Session.mk`）、MK 不出引擎（Dart 侧只见不透明句柄，`docs/01` 红线）、审计链可追溯（`vault-audit`）。
- ⚠️ **未做**：进程内存扫描（`docs/05-06 §4.1` 的「内存泄漏扫描」检测项）。安全中心页面对该项以「设计保证」呈现，未声称运行时扫描。

### T6 前端逆向 / 供应链 — ⚠️ 部分

- 加密逻辑全下沉 Rust：Dart 侧无任何密钥/明文运算（`app/lib/**` 不依赖任何密码学库；容器与索引解析均在 `vault-vault`）；
- 隐写功能的设计也维持了该边界：载荷的 AEAD 与明文拼接都在 Rust 侧完成（`vault-core/src/ffi.rs::vault_core_stego_embed/extract`），Dart 只传路径；
- ⚠️ **部分实现**（2026-09-20）：更新清单的 **Ed25519 验签**与安装包 **SHA-256 复核**已在引擎侧实现（`vault-crypto::sig` + FFI），客户端 updater 走 https 拉清单并在校验通过后才启动安装程序，未配置即 fail-closed。仍缺：发布方**签名密钥对的持有与轮换流程**、安装包**代码签名**（Windows Authenticode / macOS Developer ID）与发布服务器（基础设施决策，见 `packaging/README.md` §三）。

## 三、安全边界声明复核（§四）

| # | 声明 | 判定 | 证据 / 差距 |
| --- | --- | --- | --- |
| 1 | 引擎进程内存是唯一明文边界 | ✅ | 全部敏感操作经 FFI 传路径/句柄；`vault-core` 服务层独占 MK；Dart 侧无明文缓冲 |
| 2 | 中继零信任 | ✅ | 见 T2（relay 无 fs 调用、无解密） |
| 3 | 生物识别弱于主密码，且不削弱主密码路径 | ✅ | 两条 KEK 独立包装同一 MK（`keystore.rs`）；解绑/安全区重置只失效 `MK_wrap_bio`；冒烟「P1 生物识别绑定/解锁/解绑」 |
| 4 | 锁定态 ≠ 解锁态 | ✅ | 启动即锁定、不缓存会话（`session_controller.dart` build 返回 `SessionLocked`）；会话销毁即释放引擎槽位 |
| 5 | 销毁的最终一致性（离线设备） | ❌ | 同 T4：**队列不存在** |
