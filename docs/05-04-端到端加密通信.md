## 一、模块职责

为 P2P 同步提供信令通道与元数据保护，并实现"阅后即焚"分享。确保同步通信全程密文，中间节点无法推断正在同步的文件、大小、频率等信息。

---

## 二、功能点清单

| 编号 | 功能 | 描述 | 优先级 |
| --- | --- | --- | --- |
| F-01 | 同步元数据加密传输 | 哈希列表/块偏移/状态加密 | P0 |
| F-02 | 设备间安全信令 | 配对/同步/删除/状态信令，HMAC 校验+防重放 | P0 |
| F-03 | 阅后即焚分享 | 一次性 P2P 传输 + 限时自动擦除 | P1 |

## 三、同步元数据加密

### 3.1 元数据结构与保护

同步过程携带：文件哈希列表、块偏移、同步状态、冲突记录等。这些元数据**一律经加密后**在加密信道内传递：

| 元数据 | 保护手段 |
| --- | --- |
| 哈希列表 / 块号 | Noise 信道加密 + 逐块 AEAD |
| 块偏移 / 续传点 | 应用层加密 + 强校验 |
| 同步状态机 | 加密信令 + HMAC 防篡改 |

> 攻击者即使截获流量，也只能看到密文长度与分布，无法还原文件身份、大小与时间戳语义。

### 3.2 防频率推断

- 元数据不做明文分类分组（避免按"发送模式"反推文件类型）。
- 必要时对传输做**填充**（Padding）掩盖真实长度分布。

---

## 四、安全信令交换

### 4.1 信令协议

信令交换时序如下：

1. 设备A 构造信令 msg，并以 HMAC-SHA256 计算完整性 + 序号（防重放）；
2. 经 Noise 加密信道发送至设备B；
3. 设备B 解密并校验 HMAC 与序号；
4. 设备B 以同样受保护的方式响应设备A。

### 4.2 抗重放

- 每条信令带**单调递增序号** + 超时。
- 收到重复/乱序序号判定为异常并丢弃（联动安全中心入侵检测）。

---

## 五、阅后即焚分享

### 5.1 流程

流程链路：选文件 → 生成一次性分享会话（P2P 直连）→ 对端接收并解密 → 对端标记阅后即焚 →（打开 / 超时 1 分钟 / 关闭）→ 自动安全擦除。

- 一次性会话：传输完成后会话失效，不可复用。
- 对端打开后经设定时长或关闭文件即自动擦除，不留残留。

```dart
// 阅后即焚分享示意
class BurnShareService {
  Future<ShareTicket> createBurn(String fileId) async {
    return await ffi.vs_burn_create(session, fileId); // 一次性P2P会话
  }

  Stream<BurnStatus> monitor() => ffi.burnStream();
}
```

## 六、与其它模块的耦合

| 依赖模块 | 协作点 |
| --- | --- |
| `vault-p2p` | 复用加密信道与传输栈 |
| `vault-crypto` | Noise / HMAC / AEAD 原语 |
| `vault-audit` | 记录信令异常与阅后即焚事件 |
| `vault-vault` | 阅后即焚调用加密擦除 |
| 中继（`08`） | 跨 NAT 时信令/密文经中继转发，中继不可见任何明文与元数据语义 |

---

## 七、安全约束与测试

- **约束**：任何信令明文不出引擎；重放检测默认开启；阅后即焚使用单向擦除。
- **测试**：信令 HMAC 校验失败注入、序号重放攻击模拟、阅后即焚超时自动擦除、截获流量不可推断元数据语义。
