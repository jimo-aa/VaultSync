# VaultSync 系统整体架构设计

> 文档编号：01 ｜ 版本：V0.2 ｜ 定位：**设计文档（不含源码）**

---

## 一、设计原则

系统整体架构的设计遵循以下六条原则，后续所有模块设计均在原则约束下展开。

1. **零信任（Zero Trust）**：不信任任何第三方节点（P2P 中继、路由器、ISP、应用市场渠道）。文件全程以密文形态存在与流转，解密仅发生在用户自有设备本地。
2. **密钥与数据分离 + 密钥包装（Key Wrapping）**：主密钥 MK 由 CSPRNG 随机生成、永不变更；主密码与生物识别仅作为两把独立的"包装钥匙"（KEK）去解封 MK 的 wrapped 副本。生物识别路径依赖平台安全区（Secure Enclave / TEE / Keystore），不可用时自动降级为主密码路径，主密码路径**永不依赖**硬件安全区（桌面平台无 TEE 亦可完整工作）。主密钥永不直接加密文件。
3. **原生关键路径下沉**：所有涉及密钥、加密、擦除等安全敏感逻辑一律编入 Rust 核心引擎，前端（Flutter）仅负责展示与交互，杜绝在 Dart 层触碰明文或密钥。
4. **块级加密与增量同步耦合**：采用内容定义分块（CDC），**加密块 = 同步块 = 传输块**三位一体，使局部修改无须全局重加密，契合 P2P 增量同步。
5. **可审计**：全部敏感操作产生链式哈希审计日志，可在事后追溯且不可篡改。
6. **跨平台一致内核**：单一 Rust 内核服务 Windows / macOS / Linux / Android / iOS，前端各自适配，保证全平台行为一致。

## 二、系统逻辑分层

系统在逻辑上划分为**三层一桥**：展示层、服务层、核心引擎层，以及连接展示层与服务层的状态管理层、连接服务层与原生核心的 FFI 桥。各层组成与调用方向如下：

- **展示层（Flutter / Dart）**：页面与组件、本地化 / 无障碍、动画与导航结构。
- **状态管理层（Riverpod）**：Provider 树、App / 会话 / 同步 / 设置状态、事件流与通知。
- **服务层（Dart，仅编排）**：会话服务、保险箱服务、同步服务、设备配对服务、安全中心服务、隐写服务。
- **FFI 桥（类型安全接口契约）**：`dart:ffi` 绑定层、守护进程 / 后台任务通道。
- **核心引擎层（Rust 原生 .so/.dll/.dylib）**：`vault-core`（内核编排 / 会话）、`vault-crypto`（密钥 / AES / 擦除）、`vault-vault`（保险箱 / 索引）、`vault-p2p`（libp2p / 同步）、`vault-stego`（LSB 隐写）、`vault-audit`（审计日志）。
- **平台能力**：安全存储区（Keychain / Keystore）、本地网络 / 系统通知、文件系统。

**调用方向**：展示层 → 状态管理层 → 服务层 → FFI 桥 → 核心引擎层 → 平台能力；服务层另可经 FFI 桥的后台任务通道直达核心引擎层（用于后台能力）。

| 层 | 职责边界 | 内容 | 明文/密钥触碰 |
| --- | --- | --- | --- |
| 展示层 | 渲染、输入、导航 | 页面、组件、主题、动画、国际化 | 否（仅展示脱敏后的元数据视图） |
| 状态管理层 | 响应式状态、事件 | Provider 树、同步进度、锁状态 | 否 |
| 服务层 | 业务编排、指令转发 | 拼装 FFI 调用、错误映射、后台调度 | 否（不持有密钥） |
| FFI 桥 | 跨语言调用、内存所有权 | 原生方法绑定、回调、句柄管理 | 仅承载数据内存指针，不解析 |
| 核心引擎层 | 全部安全逻辑 | 加密 / 派生 / 同步 / 隐写 / 审计 / 擦除 | **是（本地唯一合法者）** |
| 平台能力 | OS 原生能力 | 安全存储、网络、通知、文件系统 | 视能力而定 |

## 三、核心引擎层内部结构

核心引擎以 **Rust Workspace** 组织为多个 crate，职责单一、依赖明确。各 crate 通过内部 API 协作，最外层 `vault-core` 是唯一面对 FFI 的"门面"。依赖关系如下（单向、无环）：

- `vault-core`（门面 / 编排）：依赖其余全部 crate；
- `vault-crypto`：无依赖（最底层）；
- `vault-vault`：依赖 `vault-crypto`、`vault-audit`；
- `vault-p2p`：依赖 `vault-crypto`、`vault-audit`；
- `vault-stego`：依赖 `vault-crypto`；
- `vault-audit`：无依赖。

各 crate 职责：

| crate | 职责 | 主要依赖 |
| --- | --- | --- |
| `vault-core` | 会话管理、指令编排、FFI 门面、线程池调度 | 其余全部 crate |
| `vault-crypto` | Argon2id、HKDF、AES-256-GCM、Noise、Zeroize、随机数 | 无核心定向依赖 |
| `vault-vault` | 三层密钥体系、文件加密/解密、安全擦除、分类/标签/索引 | `vault-crypto`、`vault-audit` |
| `vault-p2p` | libp2p 网络、设备配对、增量同步、断点续传、冲突解决 | `vault-crypto`、`vault-audit` |
| `vault-stego` | LSB 嵌入/提取、图片编解码 | `vault-crypto` |
| `vault-audit` | 链式哈希审计日志、事件上报 | 无 |

> 分层依赖单向、无环：`core → 各子 crate`，方向约束固定，避免循环依赖与内聚破坏。

## 四、整体部署 / 运行时视图

### 4.1 单机运行时进程模型

桌面端与移动端均采用**"UI 进程 + 原生内核线程池"**模型。核心引擎运行在独立线程池中，通过 FFI 通道双向通信，一次典型调用的时序如下：

1. 用户在 UI 发起操作（解锁 / 导入 / 同步），交给状态管理层；
2. 状态管理层经 FFI 桥异步调用核心引擎（携带上下文句柄）；
3. FFI 桥将任务入队，核心引擎线程池非阻塞执行；
4. 核心引擎通过回调向 FFI 桥上报进度 / 事件（同步状态、哈希等）；
5. FFI 桥以 Dart 事件流回传状态管理层，UI 响应式刷新；
6. 核心引擎按需访问平台能力（安全存储 / 网络 / 文件系统）。

- **单例内核**：一个进程内仅初始化一个核心引擎实例，避免多实例并发访问同一保险箱导致的数据竞争。
- **后台存活**：移动端通过后台任务通道（见 `04`）维持同步与监听，锁屏后转入受控后台。

### 4.2 多设备部署拓扑

VaultSync 为**无中心、纯 P2P**拓扑，跨 NAT 场景由**官方公共中继/信令节点 + 用户自建中继**改善（中继只转发密文，不落盘、不解密；协议与隐私边界见 `08-中继与信令协议.md`）。拓扑关系如下：

- 用户侧包含四类设备：设备A（桌面，主节点）、设备B（笔记本）、设备C（手机）、设备D（平板 / NAS）；
- 已配对设备之间两两建立直连加密信道（如 A↔B、B↔C、A↔D）；
- NAT 穿透失败时（如 A 与 C、B 与 D 之间）经可选中继 / 信令节点转发密文。

- 每台设备保存**完整的设备节点清单 + 公钥指纹**，本地维护数据源。
- 任一设备离线不影响其余设备的本地可用性；在线后自动追赶增量。

## 五、关键技术选型与理由

### 5.1 客户端框架：Flutter（Dart）

- 单一代码库覆盖 Windows / macOS / Linux / Android / iOS。
- 高帧率、自绘引擎（Skia/Impeller）适合数据密集型列表与加密缩略图渲染。
- 强类型语言便于与 Rust 侧定义**契约化接口**。

### 5.2 状态管理：Riverpod 2.x

- 编译期类型安全，支持依赖注入与自动修复，利于将 Dart 侧"服务对象"注入 UI。
- 对异步 FFI 调用（`Future`/`Stream`）有原生友好支持，贴合本系统的异步语义。

### 5.3 原生核心：Rust

- 内存安全、零运行时开销，是密码学与网络栈的首选语言。
- C ABI 稳定，可经 FFI 跨语言调用；产物为 `.dll`（Windows）/ `.dylib`（macOS）/ `.so`（Linux/Android）/ 静态框架（iOS）。
- **选择理由**：将全部密钥与明文逻辑收敛于受控的原生层，即便前端被逆向，也无法接触密钥与明文。

### 5.4 P2P：libp2p（rust-libp2p）

- 提供传输抽象、NAT 穿透（hole-punching）、中继、多路径、Noise 加密等开箱能力。
- 生态成熟，避免自研网络栈带来的安全风险。

### 5.5 FFI 桥

- 使用 `dart:ffi` 配合绑定生成工具（cbindgen 生成 C 头文件 → 绑定生成 Dart 封装）。
- 统一维护一份**接口契约规范**（见 `02`），保证两端签名一致。

## 六、跨层横切能力

| 关注点 | 方案 | 归属层 |
| --- | --- | --- |
| 会话与锁 | 会话令牌由核心引擎签发；锁定时销毁内存密钥 | 核心引擎 + 服务层 |
| 审计 | 链式哈希日志，写入加密存储 | 核心引擎（`vault-audit`） |
| 告警 | 本地通知 / 系统通知 / 可选邮件 | 服务层 → 平台能力 |
| 错误码体系 | 统一错误码表（`ERR_*`），跨 FFI 映射 | 全层 |
| 后台任务 | 受系统约束的后台同步调度器 | 服务层 + FFI 守护通道 |
| 数据持久化 | 保险箱元数据、节点清单、同步状态存于加密本地库 | 核心引擎 |

## 七、分层非功能性需求（NFR）框架

| 类别 | 目标 | 度量建议 |
| --- | --- | --- |
| 安全 | 全程密文、密钥不离引擎内存、可审计、可紧急销毁 | 常态下密钥泄露面为 0；解锁期密钥仅存于引擎进程内存 |
| 性能 | AES-NI 硬件加速下单文件流式加解密 ≥ 1 GB/s；峰值内存与文件大小无关；增量同步 CPU 占用 < 15% | 基准测试脚本纳入 CI |
| 可用性 | 断点续传、设备离线不阻塞本地 | 同步恢复率接近 100% |
| 可靠 | 增量同步一致性、冲突可解决 | 数据不丢失、不损坏 |
| 兼容 | 桌面三端（Win/macOS/Linux）为首发基线，行为一致率 100%；移动端跟进，后台同步遵循各系统约束（iOS 仅后台刷新尽力而为） | 平台差异显式记录于测试矩阵 |
| 可维护 | 分层单向依赖、契约化接口 | 无循环依赖、接口版本化 |

## 八、设计决策记录（ADR 摘要）

| 编号 | 决策 | 备选被否 | 理由起点 |
| --- | --- | --- | --- |
| ADR-001 | 安全逻辑全部下沉 Rust 原生层 | Dart 侧实现加密 | 防前端逆向泄露密钥/明文 |
| ADR-002 | CDC 块级 AES-GCM（加密块=同步块=传输块） | 整盘/容器级加密；固定 4KB 块 | 局部修改免全量重加密；固定分块遇插入退化为全量传输 |
| ADR-003 | MK 随机生成 + KEK 双路包装（密码 / 生物识别） | MK = Argon2id(密码)；单一主密钥直用 | 改密码零重加密；桌面无 TEE 可用；两解锁路径解耦 |
| ADR-004 | libp2p 自建 P2P 栈（DCUtR 打洞 + Circuit Relay v2） | 自研或上层封装 Sync 引擎 | 架构与安全可控 |
| ADR-005 | Riverpod 状态管理 | Bloc / Provider | 类型安全 + 异步友好 |
| ADR-006 | 官方公共中继 + 可自建，中继仅转发密文 | 中继存日志/缓存；纯 P2P 无中继 | 零信任 + 跨 NAT 可用性兼顾（协议见 `08`） |
| ADR-007 | 加密擦除为主，覆写按介质自动适配 | 固定三次扇区覆写 | SSD wear leveling 使扇区覆写无效且伤寿命 |
| ADR-008 | 桌面优先首发，移动端 V0.2 跟进 | 六端同步推进 | 移动端后台同步受限，先在性能上限高的平台定稳 NFR 基线 |
