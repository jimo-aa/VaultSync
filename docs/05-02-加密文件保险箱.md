# VaultSync 模块详细设计：加密文件保险箱

> 文档编号：05-02 ｜ 版本：V0.2 ｜ 类型：功能模块详细设计（**可含局部示例代码**）
> 对应计划书章节：§2.2
> V0.2 变更：分块体系改为 CDC（加密块=同步块=传输块）；修复 GCM nonce 误用；擦除改为加密擦除为主。

## 一、模块职责

本模块是 VaultSync 的数据存储核心：

- CDC 块级 AES-256-GCM 加密（流式，加密块 = 同步块 = 传输块）。
- 密钥层次（MK → FSK → FSKey，MK 定义见 `05-01`）。
- 加密擦除为主的分级擦除（密钥销毁 / 介质适配覆写 / 同步传播）。
- 分类管理（文件夹树、标签、全文索引、缩略图缓存）。

## 三、密钥层次与分块设计（展开）

派生链路如下：

主密钥 MK（CSPRNG 随机，见 `05-01`）—（HKDF-SHA256）→ 文件夹子密钥 —（HKDF-SHA256 或随机生成）→ 文件会话密钥 FSKey —（AES-256-GCM 逐块）→ 密文块 + 块 Tag + 加密元数据。

### 3.1 密钥隔离

- 每个加密文件夹独立派生 `FSK`，未来支持文件夹级共享 / 权限。
- 每个文件**随机生成**或经 HKDF 派生 `FSKey`；任一文件密钥泄露不影响其他文件。

### 3.2 内容定义分块（CDC，V0.2 核心）

- 分块算法：FastCDC（Rabin 滚动哈希指纹），**平均块 64KB，小文件（<1MB）降为 16KB**，上限 256KB。
- **加密块 = 同步块 = 传输块**：修改文件局部只重加密受影响块，增量同步只传差异块；插入数据不会使其后所有块失效（与固定分块的本质区别）。
- 同一 FSKey 下所有块共用密钥，**nonce 必须确定性**：`nonce = per-file 随机前缀(32bit) ∥ 块计数器(64bit, big-endian)`，杜绝随机 nonce 碰撞风险（GCM 经典误用）；前缀与文件 ID 一起存于加密元数据。

### 3.3 密文容器结构（概念）

每份密文文件包含：

| 区段 | 内容 | 说明 |
| --- | --- | --- |
| Header | 版本、算法标识、KDF 参数 | 明文，不含敏感内容（格式版本化见 `07`） |
| 加密元数据 | 文件名、大小、MIME、时间、nonce 前缀、块清单（块哈希+偏移） | 整体 AEAD 加密，防元数据推断；块清单同时是同步哈希列表的本地来源 |
| 数据区 | 分块 AES-GCM 密文，每块自带 16B GCM Tag | 支持随机读取与逐块校验 |
| 文件级完整性 | 整文件 SHA-256（存于加密元数据） | 重组后终验，不再单独追加尾部 Tag |

## 四、关键子流程

### 4.1 流式加密导入

1. 前端调用 `vs_vault_import(session, src, dir)`；
2. `vault-core` 生成 FSKey 与 per-file nonce 前缀；对源文件执行 CDC 分块；
3. 循环处理每个块：从文件系统读取块 → `vault-crypto` 以 FSKey + 计数器 nonce 做 AES-256-GCM 加密 → 写盘（恒定内存）；
4. 全部块写完后写入 Header 与加密元数据（含块清单、nonce 前缀、整文件 SHA-256）；
5. 登记索引 / 缩略图 / 审计。

### 4.2 流式解密导出

与导入对称：读 Header → 派生 FSKey → 逐块校验 GCM Tag → 解密输出，仍属恒定内存；重组完成后比对整文件 SHA-256 终验。

### 4.3 安全擦除（V0.2：加密擦除为主）

删除指令 → **销毁 FSKey 并从加密元数据摘除块清单**（密文留在盘上亦不可恢复，此为 SSD 场景主路径）→ zeroize 内存 / 缓存 → 按介质适配兜底覆写（SSD：单次覆写 + TRIM/平台安全删除 API；HDD：多轮覆写可选，默认关闭）→ 经 P2P 传播删除到所有对端 → 写审计。

> 三次扇区覆写在 SSD（wear leveling）上无效且伤寿命，已废弃为默认行为；介质类型由 Engine 探测决定兜底策略。

### 4.4 全文索引与检索

- 解锁后对文档提取文本 → 在 Engine 内存中构建倒排索引 → 索引以密文落盘（FSK 加密），落盘前 zeroize 明文索引副本。
- 检索时在 Engine 内解密索引到内存匹配，返回命中位置（仅回脱敏片段）；空闲超时后解密索引副本即刻清零，避免长期驻留。

## 五、接口契约与示意代码

```dart
// 保险箱服务（前端服务层）
class VaultService {
  Future<ImportResult> importFile(String src) async {
    return await ffi.vs_vault_import(session, src);
  }

  Future<void> wipe(String fileId) async {
    await ffi.vs_wipe_file(session, fileId); // 引擎执行多级擦除
  }

  Stream<SyncEvent> events() => ffi.eventStream(VaultDomain);
}
```

```rust
// 流式分块加密示意（CDC 块 + 计数器 nonce）
fn encrypt_file(fsk: &Fsk, src: &Path, dst: &mut impl Write) -> Result<()> {
    let fskey = derive_fskey(fsk, &file_id)?;
    let nonce_prefix = rand_u32();              // per-file 随机前缀
    let mut chunker = FastCdc::new(AVG_64KB);
    let mut counter: u64 = 0;
    for plain in chunker.read(File::open(src)?) {
        let mut nonce = [0u8; 12];
        nonce[..4].copy_from_slice(&nonce_prefix.to_be_bytes());
        nonce[4..].copy_from_slice(&counter.to_be_bytes()); // 确定性，禁随机
        let ct = aead_seal(&fskey, &nonce, plain, /* aad: 块序号 */)?;
        dst.write_all(&ct)?;
        counter += 1;
    }
    write_encrypted_metadata(dst, nonce_prefix, counter, file_sha256)?; // 块清单等
    Ok(())
}
```

## 六、异常与安全约束

| 场景 | 处理 |
| --- | --- |
| GCM Tag 校验失败 | 视为该块损坏/被篡改，拒绝输出并告警（可定位到具体块） |
| 空间不足 | 停止写入，保留已写密文，提示 |
| 大文件 | 强制流式，禁止一次性载入 |
| nonce 前缀冲突 | 概率 2^-32/文件，写入时校验元数据内唯一性 |
| 元数据一致性 | 加密元数据与密文强一致，块清单可探测缺块/损坏 |
