# VaultSync 威胁模型与安全边界

> 文档编号：06 ｜ 版本：V0.2 ｜ 定位：**横切专项文档（不含源码）**

---

## 一、目的

零信任不是口号，必须落在明确的对手假设上。本文档定义 VaultSync 的对手能力分级、保护目标与安全边界，作为所有模块设计的安全依据；任何模块设计若与本文冲突，以本文为准或显式升级 ADR。

---

## 二、保护目标（资产）

| 资产 | 说明 |
| --- | --- |
| 文件明文 | 保险箱内全部用户数据 |
| 文件元数据 | 文件名、大小、时间、目录结构、同步频率（降级保护：长度与时序可被观测） |
| 密钥材料 | MK / FSK / FSKey / KEK |
| 主密码 | 认证因素本身 |
| 审计日志 | 防篡改、防泄露 |

---

## 三、对手能力分级

| 级别 | 对手模型 | 能力 | VaultSync 的防线 |
| --- | --- | --- | --- |
| T1 | 网络窃听者 | 截获 P2P/中继流量、流量分析 | Noise 传输加密 + 应用层逐块 AEAD + 可选填充；只见密文与长度 |
| T2 | 恶意中继/信令节点 | 官方或自建中继作恶（存储、篡改、重放、溯源） | 中继仅见密文（`08`）；信令签名+防重放；篡改被逐块 GCM 拒绝 |
| T3 | 设备磁盘攻击者 | 拿到关机/锁定态设备的磁盘或完整文件系统拷贝 | 密文文件 + MK 仅存 wrapped 形态（锁定态内存已 Zeroize）；Argon2id 抗离线爆破 |
| T4 | 物理接触解锁态设备 | 在会话存活期间操作设备 | 自动落锁；伪装入口；紧急销毁；这层防线是"缓解"而非"根除" |
| T5 | 恶意软件同权限运行 | 与 VaultSync 同用户权限的进程，可读进程内存、挂钩 FFI | **超出威胁模型边界**（见 §五）；仅做内存擦除、最小驻留等纵深缓解 |
| T6 | 前端逆向/供应链 | 逆向客户端二进制、篡改分发渠道 | 加密逻辑全下沉 Rust 引擎；产物哈希校验与签名分发（工程化要求，见 §五） |

---

## 四、安全边界声明

1. **引擎进程内存是唯一明文边界**：解密仅发生在 `vault-core` 所在进程内存；Dart 层永不接触明文与密钥（T4/T5 的残余风险由落锁与擦除缓解）。
2. **中继零信任**：中继不作恶时的能力被限制为"转发密文比特"；中继作恶时最多实施 DoS 与流量分析（T2），不可解密、不可篡改、不可伪造信令。
3. **生物识别弱于主密码**：生物路径的攻击面包含平台安全区，其安全性以各平台安全区安全声明为准；主密码路径独立且永不被生物路径削弱。
4. **锁定态 ≠ 解锁态**：T3 仅对锁定态成立。文档所有"离线攻击"结论均以"已落锁"为前提。
5. **销毁的最终一致性**：远程/联动销毁对离线设备是最终一致（`05-06` §5.1），永不上线设备不受保护——这是设计取舍，不是缺陷隐瞒。

---

## 五、超出威胁模型的范围（明示不做）

- 同权限恶意软件的运行时攻击（键盘记录、内存抓取、调试器）——需要 OS 级隔离（虚拟机/安全桌面），超出客户端产品边界；
- 用户自身被胁迫直接交出主密码且未触发伪装/销毁——社会工程学边界；
- 官方中继运营方的流量元数据留存——通过协议设计最小化（`08`），但无法阻止 ISP 级元数据观测；
- 分发渠道被完全接管（用户未校验签名即安装被篡改的安装包）。

以上各项在 UI 与用户文档中如实披露，不做超出能力的安全承诺。
