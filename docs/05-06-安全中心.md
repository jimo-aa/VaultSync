## 一、模块职责

安全管控中枢：审计、检测、应急响应与策略配置。汇聚引擎各模块上报的安全事件，向用户提供审计、告警、紧急销毁与同步策略管理。

## 三、审计日志设计

### 3.1 链式哈希防篡改

链式哈希递推关系如下：

Log #1：h0 = H(内容) → Log #2：h1 = H(prevHash + 内容) → Log #3：h2 = H(prevHash + 内容) → ……依此链式递推，每条日志的哈希均覆盖"前一条之哈希 + 本条内容"。

- 每条日志含"前一条之哈希"，链式校验。
- **多设备审计链（V0.2）**：每设备维护独立日志链，链 ID = 设备 ID；跨设备聚合校验时按设备链分别验证，再经同步信令互传链头哈希以交叉核对，避免多设备并发写同一链导致的分叉。
- 日志加密存储，仅主密钥持有者可解密查看。

### 3.2 记录范围

| 类别 | 事件示例 |
| --- | --- |
| 保险箱 | 导入/导出/删除/安全擦除/索引重建 |
| 设备 | 配对/解配/同步起止/失败 |
| 会话 | 解锁/锁定/伪装入口 |
| 安全 | 暴力破解计数、异常设备、完整性告警 |

### 3.3 导出

- 导出为加密文件（使用专用导出密钥），仅在解锁会话进行。
- 导出事件本身也记入审计。

## 四、入侵检测与告警

### 4.1 检测项

| 检测项 | 触发条件 | 响应 |
| --- | --- | --- |
| 暴力破解 | 主密码连续失败 | 锁定 + 延时 + 计数 |
| 异常设备 | 未授权设备尝试配对/访问 | 拒绝 + 告警 |
| 文件完整性 | GCM/HMAC 校验失败 | 标记 + 告警 |
| 内存泄漏 | 扫描到未擦除密钥/明文副本 | 清理 + 告警 |

### 4.2 告警分发

- 应用内通知（Banner）。
- 可选邮件（按用户配置）。
- 系统通知。


## 五、紧急数据销毁

### 5.1 三种模式

| 模式 | 触发 | 效果 |
| --- | --- | --- |
| 本地销毁 | 设备丢失/胁迫 | 加密擦除本机数据（销毁 MK 与全部密钥槽）+ 按介质兜底覆写 |
| 远程销毁 | 从已配对设备发起 | 丢失设备联网后接收指令并执行 |
| 全设备联动销毁 | 一台触发 | 指令经 P2P/中继全量传播，所有设备依次擦除 |

**延迟销毁语义（V0.2 明确）**：离线设备无法即时收到销毁指令。销毁指令进入各设备的**高优先级信令队列**——目标设备下次上线时，信令通道在处理任何其他消息之前必须先校验并执行该指令（指令由发起方设备密钥签名，防伪造）。对"永不上线"的设备，销毁无法保证，此风险边界在 UI 与文档中明示。

### 5.2 流程

流程链路：触发紧急销毁 → 确认（需输入确认短语）→ 通过后签发销毁指令（发起方设备密钥签名）并发往所有已配对设备 → 各设备执行加密擦除（销毁密钥槽 / 密文 / 审计，按介质适配兜底覆写），同时尽力写入最终审计记录。

> 前端采用强红告警 + 确认短语二次把关，降低误触。

- 启用/停用均记审计。

## 八、异常与安全约束

| 场景 | 处理 |
| --- | --- |
| 审计日志被篡改 | 链式校验失败即告警，定位被改点 |
| 紧急销毁进行中 | 显示单向进度，不允许普通操作取消 |
| 策略变更 | 记审计，并校验不违背安全下限（如不可全时段禁止同步导致积压） |
