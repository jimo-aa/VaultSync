## 0. 全局约定（先读，后面各节都用得到）

| 项 | 内容 | 出处 |
| --- | --- | --- |
| 错误码空间 | 0–13，**只增不复用**；前端必须显式映射，不得原样透传 | （05-01 §五.1.4）（05-01 §五.3） |
| 中继错误空间 | `R1–R17` 为独立空间，**必须显式映射，不得原样返回** | （AGENTS.md；本文档组未展开，仅登记为约束） |
| 句柄 | 0 与哨兵值不得当指针；`open` 返回 0/9/11 三态分流 | （05-01 §五.1.2）（05-01 §五.4） |

| 会话状态 | `Active` / `Maintenance` / `NeedsRecovery` / `RO`（`RO` 为修饰位） | （05-01 §五.2）（07 §三.5） |
| 脱敏纪律 | 审计 detail 一律结构化短串（`action key=value`），**不写明文内容、不写文件名** | （05-06 §三.7） |
| 呈现纪律 | 颜色 + 文字同时呈现，**不得只用颜色** | （05-06 §四.1） |
| 不渲染纪律 | 能力未交付 / 已是目标版本时**整块不渲染**（不置灰、不写「即将推出」、不写「已是最新」） | （05-01 §六）（05-06 §四.3）（05-06 §六）（05-06 §七）（07 §七.3）（07 §五.2） |

| 引擎不做平台调用 | 引擎**不下发用户可见文案**，只发结构化事件；文案由服务层 `notify_dispatch.dart` 映射为「级别 + ARB 键 + 参数」 | （05-06 §四.3） |

## 2. 弹窗 / 模态清单

> 每条含：触发点 / 标题 / 内容字段 / 按钮（含主次与禁用条件）/ 校验规则 / 失败语义 / 关闭方式。

### 2.1 身份认证与解锁（05-01）

**M-01 主密码设置（首启）**
- 触发点：P1-01 首启引导（无 `VSVB` 头部）。
- 标题：`设置主密码`。⚠️推断（文档未给标题原文，只给流程）。
- 内容字段：主密码输入框（掩码）、确认主密码、**强度评估条**。
- 按钮：`创建保险箱`（主，**禁用条件：两次输入不一致或强度未达门槛**）、`退出`（次）。
- 校验规则：Argon2id 参数组 `kdf_ver=1`（64 MiB, t=3, p=2）+ HKDF-SHA256；每次设置密码随机生成新 `salt`（（05-01 §3.4）（07 §5.4））。强度门槛文档未给数值 → **⚠️需产品定**。
- 失败语义：③–⑤ 任一步失败 → **删除已写头部与段目录整体回滚**；⑥ 失败 → 目录整体删除并返回 **码 3**；**绝不留半成品库**（（05-01 §4.1））。
- 关闭方式：创建成功前不可关闭（防半成品）；`退出` 走整体回滚。

**M-02 解锁失败与冷却提示**
- 触发点：解锁返回 **码 1**（密码错，附 `out_wait_ms`）/ **码 2**（冷却中，附剩余 ms）。
- 标题：`密码错误` / `已进入冷却`。⚠️推断。
- 内容字段：**剩余等待时间（倒计时）**；失败计数（文档要求审计记「计数、冷却剩余」，UI 是否显示计数未强制 → ⚠️推断可选）。
- 按钮：`重试`（主，**禁用至倒计时结束**）。
- 校验规则：指数冷却；**伪装密码尝试共用同一计数器**（按 `data_dir` 域计数）（（05-01 §4.2 第 1 步）（05-01 §4.8））。
- 失败语义：`verifier` 失败 **与密码错同形**（不泄露「头部被调包」）（（05-01 §4.2））。
- 关闭方式：可关闭；关闭后回到解锁屏。

**M-03 生物识别失效 → 引导重新绑定（码 5）**
- 触发点：`unlock_bio` 返回 **码 5**（安全区失效 / 绑定变更 / 生物登记变化）。
- 标题：`生物识别已失效，请重新绑定`。⚠️推断。
- 内容字段：平台差异说明（Windows/macOS：安全区重置；Android：新增/删除指纹即失效；iOS：生物登记变更即失效）。
- 按钮：`用主密码解锁`（主）、`重新绑定`（次，需先密码解锁）。
- 失败语义：**主密码路径不受影响**（（05-01 §4.2）（05-01 §4.4））。
- 关闭方式：可关闭。

**M-04 生物识别绑定确认**
- 触发点：设置 · 生物识别 → `绑定`。
- 标题：`绑定生物识别`。⚠️推断。
- 字段：是否已处于解锁态（**绑定需先密码解锁**）。
- 按钮：`绑定`（主）、`取消`。
- 校验：`vault_core_bind_bio(session)`（3 参，typedef 不与其他复用）。
- 失败语义：安全区不可用 → **码 4**（**不报错、隐藏入口**）；绑定过程失败 → **码 3** 且**保留原头部**（先建后拆：新副本写入成功后才清除旧副本）（（05-01 §4.4））。
- 关闭方式：可关闭。

**M-05 生物识别解绑确认**
- 触发点：设置 · 生物识别 → `解绑`。
- 按钮：`解绑`（危险，主）、`取消`。
- 失败语义：同上（码 3 保留原头部）。
- 副作用：`vault_core_unbind_bio` → 清 `flags.bit0` 并作废 `KEK_bio`；审计 `bio.unbind`（（05-01 §4.4）（05-01 §七.1））。
- 关闭方式：可关闭。

**M-06 修改主密码**
- 触发点：设置 · 修改主密码。
- 字段：旧密码、新密码、确认新密码。
- 按钮：`修改密码`（主）、`取消`（次）。
- 校验：引擎重派生 `KEK_pwd` 解封成功即证明旧密码正确；新 `salt` 生成。
- 失败语义：旧密码错 → **走 §4.2 冷却路径（码 1，附等待 ms）**；冷却中 → **码 2**（（05-01 §4.3））。
- 关闭方式：可关闭。
- 影响面提示（必须出现）：**从属密钥区、`MK_wrap_bio`、FSK / FSKey / 全部密文一律不动**（零重加密）（（05-01 §4.3））。

**M-07 从属密钥轮换（F-09）**
- 触发点：设置 · 从属密钥管理 → 选中一条或多条 → `轮换`；或安全中心（例：怀疑分享密钥泄露）。
- 标题：`轮换从属密钥`。⚠️推断。
- 字段：`key_id` 多选（1 索引 / 2 搜索 / 3 分享 / 4 订单 / 5 隐写载荷 / 6 链键 / 7 审计导出 / 8 发现指纹盐）；每条的**影响域**与**是否需要维护态**提示；确认短语输入（走 `rotate_mk_begin` 的 opts 扩展位 `{"scope":"derived_only","keyIds":[...]}`）。
- 按钮：`开始轮换`（主）、`取消`（次）。
- **禁用/前置条件**：`key_id ∈ {1, 2, 6, 7}` 的轮换**必须**在维护态下进行（写冻结），并对受影响结构做一次全量重写；`key_id ∈ {3, 4, 5, 8}` 无历史数据依赖，可即时轮换（（05-01 §4.5））。只读（码 9）/ 非维护态调用非法组合 → **码 9 / 码 10**（（07 §八 测试 2））。
- 字段级影响域文案（必须可核对）：
  - `key_id=1` 索引 → 索引段整体重写（维护态）。
  - `key_id=2` 搜索 → **搜索令牌全部重建**（倒排重写）。
  - `key_id=3` 分享 → **既有票据作废**（`seed_shares` 递增，旧票据校验失败），非重写。
  - `key_id=4` 订单 → 队列整体重加密。
  - `key_id=5` 隐写载荷 → 新图用新值；**已流出的旧图无法追回（如实声明）**。
  - `key_id=6` 链键 → **必须在维护态下重写全部审计段**；轮换事件本身写入新链段并记录旧段尾哈希。
  - `key_id=7` 审计导出 → 旧信封保持可解（如实声明）。
  - `key_id=8` 发现指纹盐 → 指纹与配对短码**全部变化**；未配对设备显示为新指纹，需重新核验；已配对设备需更新指纹记录。
  - 出处：（07 §2.1 第 3–10 行）
- 失败语义：轮换中崩溃 → 同 §4.6 续做判据（`rotation_id` 标记）；受影响的从属密钥未能全部重包装 → **码 11**，**不允许「一半旧值一半新值」**（头部写入单次 tmp+rename 天然原子）（（05-01 §4.5））。
- 关闭方式：可关闭（未发起时）。

**M-08 MK 轮换发起（确认短语）**
- 触发点：设置 · MK 轮换 → `发起 MK 轮换`。
- 标题：`轮换主密钥`。⚠️推断。
- 字段：主密码输入、**确认短语**（`confirm_phrase`）、影响面说明（全库重加密 + 仅重包装 8×64 B ≈ 512 B 从属密钥）。
- 按钮：`开始轮换`（危险，主）、`取消`。
- 校验：`rotate_mk_begin(session, confirm_phrase, out_task_id)`；校验主密码 + 确认短语。
- 失败语义（逐条在 UI 呈现）：**码 1** 确认短语/主密码错（进冷却）；**码 10** 已在维护态；**码 2** 冷却中；**码 9** 只读租约；**码 3** 恢复文件写失败（**不进入轮换，头部仍 idle**）（（07 §3.2）（05-01 §5.3））。
- 关闭方式：可关闭。
- ⚠️ **确认短语的具体文本与校验规则文档未定义**（只给出参数名 `confirm_phrase` 与「校验主密码 + 确认短语」）→ 原型需占位并标注待产品定。

**M-09 轮换进度浮层 / 维护横幅**
- 触发点：`rotate_mk_begin` 返回后；或启动序列读到 `rotation_state ∈ {1,2}`。
- 内容字段（对齐 `rotate_mk_status` JSON）：`rotationState ∈ idle|in_progress|pending_ack`；`rotationId`（hex）；`phase ∈ mark|rekey|propagate|done`；`progress {done, total, files, folders}`；`interrupted`；`propagation[] {peerId, state ∈ acked|pending|offline, vcAdvanced}`；`derivedKeysLegacy`（（05-01 §5.3））。
- 文案（必须原样出现）：**「MK 轮换进行中 NN%，可随时关闭应用，下次启动自动继续」**（（07 §3.4 I3））。
- 按钮：`暂停/放弃`（见 M-11）、`查看设备传播`（M-14）。
- 会话语义：`Maintenance`（码 10），业务写入冻结、读取与导出允许、**擦除/销毁不受冻结**（（05-01 §3.6）（07 §3.5））。
- 关闭方式：**可关闭应用**（这是文档明确承诺「可随时关闭应用」）；（07 §3.4 I3）

**M-10 轮换自动续做耗尽 → 显式确认**
- 触发点：同一 `rotation_id` 的**自动**续做已达 3 次；`rotate_mk_status` 报 `interrupted=true` **且** `autoResumeExhausted=true`。
- 标题：`轮换已多次中断，请确认后继续`。⚠️推断。
- 字段：已尝试自动续做次数、上次中断位置。
- 按钮：`继续轮换`（主，调 `rotate_mk_resume`）、`放弃`（→ M-11）。
- 规则：第 4 次起**不自动续做**；**不提供「无限自动重试」开关**（（07 §3.6））。
- 关闭方式：可关闭（状态保持「待确认」）。

**M-11 轮换暂停 / 放弃确认**
- 触发点：M-09 横幅 → `暂停/放弃`。
- 标题：`放弃本次轮换？`。⚠️推断。
- **按钮随状态分叉**：
  - `state=1` → 提供回滚入口（M-12 `用旧 MK 回滚数据面`）。
  - `state=2` → **只能完成传播**（数据已换钥，不可逆）；回滚入口**不提供**（（07 §3.6）（07 §3.4 注））。
- 校验/规则：回滚入口**仅在 `state=1` 且本会话仍持有旧 MK 时**可见；`state=2` 之后只提供「完成传播」与「导出取证」（（07 §3.4 注））。
- 关闭方式：可关闭。

**M-12 用旧 MK 回滚数据面（危险二次确认）**
- 触发点：M-11 / P1-06（`state=1` 且持旧 MK）；或轮换第 5 步返回错误后的失败分支。
- 标题：`用旧 MK 回滚数据面`。⚠️推断。
- 内容：影响说明（数据面回滚到旧 MK，沿用 V1.0 保护区机制；`rotation_state=1 → 0`）；`VSRR` 恢复文件删除说明。
- 按钮：`确认回滚`（危险，主）、`取消`。
- 失败语义：轮换第 5 步返回错误时提供；恢复文件缺失 / `digest` 不匹配 → **码 11 且不自动猜测**（（05-01 §4.6）（05-01 §六））。
- 关闭方式：可关闭。

**M-13 并发轮换冲突告警（`rotationConflict`）**
- 触发点：两端同时发起轮换，败者已到 `state=2`（头部已提交，不可逆）。
- 级别：**`danger`**（进 `/alarm`）+ 审计 `rotation.conflict`。
- 内容：`rotationId` 对比（**hex 字典序较小者胜出**）；「不自动回滚」说明；**跨端同步会被拒绝**（对端解封 `ct` 失败 → `mk_mismatch`）；处置动作 = **在对端重新发起一次轮换**。
- 按钮：`重新发起轮换`、`导出取证`、`我知道了`。
- 文案（必须出现）：**「需要重新发起轮换」**（（07 §4.3））。
- 关闭方式：`danger` 强告警不可 `Esc` 关闭，须点语义动词按钮（（05-06 §四.3））。

**M-14 设备传播详情（逐对端）**
- 触发点：M-09 / 设备页「待补推」。
- 字段：逐对端 `{peerId, state ∈ acked|pending|offline, vcAdvanced}`。
- 规则文案：**「向量时钟未推进即视为未传播——不允许把『指令已入队』呈现为『已完成』」**；对端离线 → 标**「待补推」**（（05-01 §3.7）（07 §四.2）（07 §四.4））。
- 按钮：`重新推送`（⚠️推断）、`关闭`。
- 关闭方式：可关闭。

**M-15 远程锁定发起**
- 触发点：设备页 → `远程锁定`。
- 字段：目标设备选择（`peer_id`；`peer_id = NULL` 表示**全部已配对设备**）。
- 按钮：`发送锁定指令`（主）、`取消`。
- 失败语义：`peer_id` 无配对记录 → **码 7**；离线对端 → 指令入队（返回 **0** 且 `pending=true`，**UI 标「待投递」，不得显示「已锁定对端」**）；队列写入失败 → **码 3**（（05-01 §4.7））。
- 关闭方式：可关闭。

**M-16 远程锁定接收提示**
- 触发点：接收侧校验四条通过（① 签名有效；② `target == 本机 device_id`；③ 未过期 `expires_ms`；④ `issued_ms` 与本机时钟偏差 ≤ 300 s）→ **立即锁定**（Zeroize 全部密钥 + 释放租约）。
- 内容：**显示来源设备**；文案 **「已由 <设备名> 远程锁定」**。
- 按钮：`重新解锁`。
- 规则：**不做二次确认**（与销毁指令同级通道；若锁定要确认而销毁不要，逻辑不自洽）（（05-01 §4.7））。
- 失败语义：校验失败 → 丢弃 + 审计 `lock.remote.reject` + `ERROR_DIAG`（用户侧不弹错误框，⚠️推断）。
- 关闭方式：锁定后自动转为解锁屏。

**M-17 本地销毁确认（危险二次确认）**
- 触发点：安全中心 · 紧急销毁 → `本地销毁`（`vault_core_destroy_local`）。
- 字段：擦除强度声明（见 M-24）；目标范围（保险箱头部 + 数据目录 + 按介质兜底覆写）。
- 按钮：`确认销毁本机数据`（危险，主）、`取消`。
- 失败语义：**租约被占（码 9）时禁止销毁**（避免与另一进程争抢数据目录）；本地销毁**不依赖会话**（可由锁屏直接调用）；**维护态下允许**（唯一例外）（（05-06 §5.5））。
- 关闭方式：确认前可关闭。

**M-18 全设备联动销毁确认**
- 触发点：`vault_core_p2p_destroy_queue_all`。
- 字段：逐台设备列表（指令入加密队列，**收到 ACK 才出队**）。
- 按钮：`确认全设备销毁`（危险，主）、`取消`。
- 失败语义：队列写入失败 → **码 3**（明确报错，不静默；已入队部分保留）；对端拒绝/验签失败/target 不匹配 → **一律不执行**并回 `DestroyReject`（**码 6 / 码 13**）（（05-06 §5.5））。
- 关闭方式：确认前可关闭。

**M-19 远程销毁武装（延迟 + 时效窗口）**
- 触发点：`vault_core_p2p_destroy_arm`。
- 字段：`target`；`delayMs`（延迟，`deadlineMs` 为**绝对时刻**，不用剩余秒数）；**时效窗口** `expires_ms`（默认 `ts_ms + 7 天`；可选 `0 = 不过期`）。
- 按钮：`武装`（危险，主）、`取消`；`expires_ms = 0` 时触发 M-20 二次确认。
- 校验：签名体 v2 = `vsync-destroy:{target}:{delay_ms}:{ts_ms}:{expires_ms}`；接收端 `now > expires_ms` → **丢弃 + 不执行**；`expires_ms == 0` → 按不过期处理（仍入审计）。
- 失败语义：**武装状态落盘失败 → 拒绝武装（不留「只在内存里的倒计时」）**，**码 3**；`proto_ver = 1` 对端 → 按对端版本签发 v1 签名体（无时效），标 `legacy_signature=true`（（05-06 §5.2）（05-06 §5.4））。
- 关闭方式：确认前可关闭。

**M-20 「指令将永久有效」二次确认**
- 触发点：M-19 中选择 `expires_ms = 0`。
- 文案（必须出现）：**「该指令将永久有效」**。
- 按钮：`我确认永久有效`（危险，主）、`改为 7 天后过期`（次）、`取消`。
- 出处：（05-06 §5.4）。

**M-21 时钟异常显式确认**
- 触发点：`ts_ms` 超前本机时钟 > 24 h（或 `now + 5 min < ts_ms`）→ 拒绝并要求用户**显式确认**（防通过操纵时钟绕过 TTL）。
- 内容：本机时钟 vs 指令时间戳对比；拒绝原因说明。
- 按钮：`仍然执行`（危险，主）、`丢弃指令`（次，默认）。
- 失败语义：拒绝时审计 `destroy_order_clock_skew`（（05-06 §5.4））。
- 关闭方式：可关闭（等同丢弃）。

**M-22 销毁取消确认**
- 触发点：`vault_core_p2p_destroy_cancel`（清除 `armed` 记录并落盘，**幂等**）。
- 按钮：`取消销毁`（主）、`返回`。

**M-51 审计写入连续失败 → 审计项转灰「审计不可用」**
- 触发点：审计写入失败**连续 ≥ 10 次**。
- 规则：安全中心审计项**转灰**并提示**「审计不可用」**；审计写入失败**不阻断业务**，但必须发 `ERROR_DIAG(22, component=vault-audit)`。
- 出处：（05-06 §八）（05-06 §3.3）。

**M-52 通知权限被拒 → 降级提示**
- 触发点：系统通知权限被拒（返回 **码 4**）。
- 规则：降为**应用内 `warn` 级** + 设置页提示**「系统通知已关闭」**；移动推送未授权 → 矩阵中该端该渠道标**「未授权」**，其余渠道不变。
- 出处：（05-06 §四.3）。

**M-53 伪空间创建失败（码 3）**
- 触发点：伪装密码路径创建伪空间失败。
- 规则：**码 3，且不改真空间任何字节**；伪空间内容不可被真空间会话访问（句柄域隔离，越权调用 → **码 7**）；进入伪空间后**真空间调用一律拒绝**（码 7）；**审计不泄露真伪**。
- 出处：（05-01 §4.8）（05-01 §六）。

**M-54 检测项无数据（灰态，非 0）**
- 触发点：任何检测项 `checked == 0` / 从未自检。
- 规则：一律显示**灰（`stale` Token）+「未扫描 / 无数据」**，**不显示 0 也不显示绿**。
- 出处：（05-06 §八）（05-06 §4.1）。
