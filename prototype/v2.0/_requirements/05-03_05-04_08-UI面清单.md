## 1. 页面清单

### 1.1 一级页面

#### P1 设备与配对（Devices）
- **入口**：左侧导航「设备」；配对成功的 toast/通知点击也回到本页（05-03 §3.3 配对成功后写 `peers.enc` + 审计 `p2p.pair`）。
- **内容区块（自上而下，顺序即建议 DOM 顺序）**：
  1. **本机卡**：本机 deviceId（`self.deviceId`）、公钥指纹（`self.fingerprint`，显示前 8 hex + 展开显示全量）、监听端口（`self.port`）、本机名（来自 OS API，不是 mDNS 实例名）（05-03 §3.1、§3.4）。
  2. **发现卡**（局域网设备列表）：数据源 = `vault_core_p2p_discover` 快照 `candidates[]`（05-03 §3.4）。每行字段：
     - 已配对设备：名称（配对后从 `peers.enc` 取）+ 指纹前缀 + `paired=true` + 地址列表（`addrs[]`：`addr`/`transport`/`reachable`/`rttMs`）。
     - **未配对设备：`deviceId` 与 `name` 为 `null`，必须显示为「局域网设备 · 指纹 A3:F1…」**（05-03 §3.1、§3.4）。
     - `reachable=false` 的行显示为不可达（不显示「离线」，因为发现探测未打洞、未建长连接）（05-03 §3.4）。
     - `matchCodeExpiresMs` 倒计时（配对中显示，见 §4 向导）（05-03 §3.3、§3.4）。
  3. **四种载体入口区**（05-03 §3.3）：① 发现（本卡列表内点击）② 二维码（生成 / 扫码）③ 邀请码（生成一次性码）④ 手动（地址 + 码）。
  4. **开关行**：「局域网发现」开关（设置页同一开关的镜像入口）（05-03 §3.1「设置页可关闭发现」）。
  5. **降级提示条**：mDNS 绑定失败（端口占用/权限）→ `3` 且载荷 `enabled=false`，本卡**显示降级入口（邀请码 / 扫码 / 手动）并明说「局域网发现不可用」**（05-03 §3.4）。
- **关键操作按钮**：
  - 「添加设备」（主按钮，弹出载体选择，见 §2 弹窗 M1）。
  - 「立即重新发现」（触发 `discover` 快照重拉；注意：收到 `PEER_STATE(state=discovered)` 帧后**自动拉一次快照重建列表**，与 `VAULT_CHANGED` → `vault_list` 同款纪律）（05-03 §3.4③）。
  - 每行右键/悬浮：「配对」「查看诊断路径」（跳到 P5 路径诊断）「解绑」（`vault_core_p2p_unpair`，危险操作见 §8）（05-03 §3.3）。
  - 发现卡整卡渲染开关：`CAP_DISCOVERY` 未置位 → **发现卡整卡不渲染**（05-03 §3.4④）。
  - 「扫码」载体仅在相机可用时渲染；不可用/权限被拒 → **不渲染**（不置灰、不写「即将推出」）（05-03 §3.5）。

#### P2 同步总览（Sync）
- **入口**：左侧导航「同步」（05-03 §5.1–§5.5、§七）。
- **内容区块**：
  1. **统计卡区**（见 §5.1 逐指标）。
  2. **传输队列分节**（见 §5.2）。
  3. **被跳过/手动待同步分节**（`skipped[]`，见 §5.6）（05-03 §七）。
  4. **冲突解决分节**（见 §5.4）（05-03 §6.3、§6.4）。
  5. **策略摘要行** + 「同步策略」设置入口（弹窗 M6）（05-03 §5.5）。
- **关键操作按钮**：「全部暂停」「全部恢复」「清除已完成」「同步策略」（主）；队列行内 ⏸/▶/✕（次）（05-03 §5.2、§5.4）。

#### P3 加密通信（Secure Channel）
- **入口**：左侧导航「通信」（05-04 §五、§六）。
- **内容区块**：
  1. **会话列表**（配对设备之间的一次性 P2P 会话；burn 会话单列）（05-04 §5.2）。
  2. **消息/任务线程区**（burn 的 `TASK_*` 进度复用队列行 `QueueRow` / `TransferRing`）（05-04 §六）。
  3. **身份核验标记区**（短码 / 指纹前缀 / `legacy_signature` 提示）。
  4. **中继与路径状态区**（`relay{id, sessionTtlMs, rateLimited}` + `paddingTier`）（05-03 §4.4、08 §3.7）。
  5. **阅后即焚入口**：仅 `CAP_BURN_SHARE`(13) 置位时渲染；未置位 → **整个入口不渲染**（05-04 §5.5）。

#### P4 安全中心 / 诊断（Security & Diagnostics）
- **入口**：左侧导航「安全中心」；设备行「查看诊断路径」深链；`ERROR_DIAG(22)` 与 danger 告警的落地页（05-04 §4.5、§5.4）。
- **内容区块**：
  1. 信令异常计数区：`p2p_status.signal.{rejectedReplay, rejectedOutOfWindow, decryptFailed}`（05-04 §4.4 拒绝的代价、08 §4.1）。
  2. 路径诊断区：`vault_core_p2p_path_status` 全字段（见 §6.5）。
  3. 填充诊断区：`padding{padTier, floorBreached, legacyPeer, overheadRatio, frameLenHistogram}`（05-04 §3.6①）。
  4. 协议协商诊断区：`proto{legacyPeer}` + `sync proto_downgrade from=2 to=1` 审计条目（08 §4.5）。
  5. 中继诊断区：`rateLimited` / `closeReason`（08 §五「限速触发」分支）。
  6. danger 告警位（全屏级）：`EraseFailed`（burn 擦除失败保留并告警）（05-04 §5.4）。
  7. 「导出脱敏诊断包」：地址一律哈希前缀处理（05-03 §4.4③）。

#### P5 设置（Settings）
- **入口**：左侧导航「设置」或标题栏齿轮。
- **内容区块（本节涉及的）**：
  1. **发现**：开关「局域网发现」（关闭后不发也不收，只保留邀请码/扫码/手动三种载体）（05-03 §3.1）。
  2. **虚拟接口**：VPN / 容器网桥 / Hyper-V 虚拟网卡默认排除的勾选列表（用户可显式勾选加入候选）（05-03 §3.2）。
  3. **相机权限**：权限被拒后「前往系统设置」入口（记住拒绝，不再重复弹窗）（05-03 §3.5）。
  4. **中继**：自建中继列表增删 + 顺序调整 + 逐个录入 token + 「允许使用官方公共中继」开关（`allowPublicRelay`）（08 §3.6、§3.2）。
  5. **同步策略**：全字段表单（弹窗 M6 亦可）（05-03 §5.5）。
  6. **阅后即焚默认值**：Offer TTL（默认 15 min，0 = 不自动过期）、`open_timeout`（默认 60 s，可配 30–300 s）（05-04 §5.3）。
  7. **危险区**：解绑设备、远程销毁/锁定指令签发（破坏性指令 TTL 默认 7 天，0 = 不过期需二次确认）（08 §4.3、§4.2）。

### 1.2 二级页面（建议为独立路由，非弹窗）

#### S1 单设备详情（Device Detail）
- **入口**：设备行双击 / 右键「详情」。
- **区块**：设备名称、deviceId、公钥指纹（全量 + 短码核验入口）、已配对时间、载体类型（发现/二维码/邀请码/手动，审计 `p2p.pair` 的 detail）（05-03 §3.3、§8.1）。
- **路径区**：当前路径（`direct|hole_punch|relay`）、`pathSinceMs`、`attempts{direct,punch,relay}`、`candidates{local,remote,relayObserved}`、`lastFailure{reason,atMs}`、`relay{id,sessionTtlMs}`、`bytesIn/bytesOut/rttMs/paddingTier`（05-03 §4.4②）。
  - **隐私纪律：只显示候选数量与类型，不显示对端 IP / 端口明文**（05-03 §4.4③）。
- **降级说明行**：任何降级带 `reason`，在此展开一行说明，**3 s 自动收起**（动效 #10）（05-03 §4.2）。
- **操作**：「同步此设备」「解绑」「发送销毁指令」「发送锁定指令」（后两者危险，见 §8）。

#### S2 传输队列详情（Queue Detail）
- **入口**：P2 队列分节的「查看全部」。
- **区块**：全量任务行（`task_id` 为唯一键）、优先级分组（destroy > interactive > background）、并发占位（默认 3，可配 1–8）、队列深度上限提示（1024，超出返回 `7`）（05-03 §5.2）。
- **操作**：单行 ⏸/▶/✕；「提升优先级」（仅 interactive，且 interactive **不抢占** background，只在管道空闲时先取）（05-03 §5.2）。

#### S3 单文件同步详情（File Sync Detail）
- 详见 §5.3。

#### S4 冲突解决（Conflict Resolve）
- 详见 §5.4。

#### S5 路径与中继诊断（Path & Relay Diagnostics）
- 详见 §6.5。

#### S6 阅后即焚会话详情（Burn Session Detail）
- **入口**：P3 会话行 / burn 队列行。
- **区块**：`phase`（状态机 11 态，见 §6.3）、`opened`、`erased`、`eraseClass`、`bytes`、`retries`（0–3）、`peerFingerprintPrefix`（05-04 §5.7①）。
- **操作**：「立即擦除」（显式）、「保存到…」（危险，二次确认）、「撤销分享」（Offer 期）（05-04 §5.3、§5.4）。

#### S7 中继配置（Relay Config，自建运维面）
- **入口**：设置 → 中继 → 编辑。
- **字段**：`bind`（默认 `0.0.0.0:47471`）、`tokens[]`（为空则启动失败，不存在无鉴权模式）、`limits`、`ops.enabled`（默认 false）、`ops.bind`（**必须 loopback**，否则启动失败）、`ops.token`（`ops.enabled=true` 而此项为空 → 启动失败）、`log.rooms`（默认 true）、`max_frame`（默认 `65541`）（08 §3.2）。
- **三条纪律的 UI 呈现**：已配对会话的时长/空闲/字节三类上限**必须同时存在**，任一配为 `0` → 启动失败并在错误信息中指出该项（08 §3.3 纪律 1）。

## 2. 弹窗 / 模态清单

> 仓库约定：**所有二级界面用弹窗（modal），不用滑入抽屉**（AGENTS.md）。以下标题均为建议文案。

### M1 添加设备（载体选择）
- **触发**：P1「添加设备」；发现卡降级提示条。
- **标题**：「添加设备」
- **内容字段**：四个载体按钮块 —— ① 从局域网发现（列表内选）② 扫码 ③ 邀请码 ④ 手动输入地址与码（05-03 §3.3）。
- **渲染条件**：`CAP_DISCOVERY` 未置位 → 「发现」块**不渲染**；相机不可用/权限被拒 → 「扫码」块**不渲染**（不置灰、不写「即将推出」）（05-03 §3.4④、§3.5）。
- **按钮**：主「继续」；次「取消」。
- **关闭方式**：ESC / 点遮罩 / 取消。

### M2 生成邀请码（Offer 侧）
- **触发**：M1 → ③。
- **标题**：「邀请码配对」
- **内容字段**：一次性码（大号、可复制）、二维码（同一串）、`fingerprint`、`deviceId`、`port`、有效期倒计时（TTL 由 `pair_begin` 返回值承载）（05-03 §3.3）。
- **按钮**：主「复制邀请码」；次「重新生成」「关闭」。
- **失败语义**：码错误/过期 → `1` 或 `6`（**分渠道提示**）（05-03 §3.3）。
- **校验**：无输入项。

### M3 输入邀请码 / 手动配对（Join 侧）
- **触发**：M1 → ③/④；发现行「配对」。
- **标题**：「加入配对」/「手动配对」
- **内容字段**：
  - 载体③：`code`（一次性邀请码，单行输入）。
  - 载体④：`addr`（`ip:port`）+ `code`（05-03 §3.3 表）。
- **按钮**：主「配对」（禁用条件：③ 时 `code` 为空；④ 时 `addr` 或 `code` 任一为空。**注意：手动配对在 V2.0 降级为兜底路径**，UI 应把它放在载体列表最后并标「一般不需要」（05-03 §二 F-04））；次「取消」。
- **校验**：`addr` 格式（`ip:port`）；`code` 非空。
- **失败语义**：配对码错误/过期 → `1` 或 `6`（分渠道提示）；对端格式不兼容 → `6`；能力缺口（发现关闭）→ `13`；成功 → 写 `peers.enc` + 审计 `p2p.pair`（05-03 §3.3）。
- **关闭方式**：ESC / 遮罩 / 取消。

### M4 短码核对（MITM 防线，必过步骤）
- **触发**：四种载体**统一汇入**双向认证后（05-03 §3.3 图），M3/M2/M1-扫码 成功后进入。
- **标题**：「核对配对码」
- **内容字段**：**双端独立计算**的 6 位十进制短码（`shortCode = 十进制(HKDF(SHA256(pk_a ‖ pk_b ‖ role), "pair-code")[0..4]) % 1_000_000`，补零 6 位）；双方指纹（可用于人工比对）；120 s 倒计时（`matchCodeExpiresMs`）（05-03 §3.3）。
- **按钮**：主「一致，完成配对」；次「不一致，取消」（危险色，见 §8）。
- **禁用条件**：倒计时归零 → 主按钮禁用 + 提示「配对码已过期，请重新发起」（过期需重新发起）（05-03 §3.3）。
- **校验**：用户人工比对；说明文案必须写「两端显示同一 6 位码才可继续；中间人无法让两侧算出同一个码」。
- **失败语义**：不一致 → 终止配对、清理会话、审计。

### M5 扫码（相机）
- **触发**：M1 → ②（仅相机可用时）。
- **标题**：「扫描配对二维码」
- **内容字段**：取景框 + 解析状态。
- **校验/失败语义**：解析失败 → 「未识别，请重新对准」；二维码 `exp` 过期 → 「二维码已过期，请在另一台设备重新生成」（05-03 §3.5）。
- **隐私约束（写入实现注释与 UI 说明）**：相机帧**不落盘、不进剪贴板、不留日志**（05-03 §3.5）。
- **关闭方式**：ESC / 遮罩 / 取消。

### M6 同步策略设置（全字段）
- **触发**：P2「同步策略」/ 设置页。
- **标题**：「同步策略」
- **内容区块与字段**：见 §5.7（全字段与枚举）。
- **按钮**：主「保存」（只读降级下禁用/返回 `9`；维护态返回 `10`）；次「恢复默认」「取消」。
- **失败语义**：策略写入失败 → `3`（**保留旧策略**）（05-03 §5.5）。
- **关闭方式**：ESC / 遮罩 / 取消；有未保存改动时二次确认。

### M7 冲突解决（保留 / 丢弃 / 安全丢弃）
- **触发**：P2 冲突分节行；`ConflictPair` 徽标（`color.quarantine`）（05-03 §6.4③）。
- **标题**：「解决冲突」
- **内容字段**：A/B 两侧条目（`keep_id` / `drop_id`）、`mergeClass`（`auto` / `conflict` / `replace`）、生成时间、来源设备、副本命名（`{name}.conflict-{ts}`）（05-03 §6.4③）。
- **按钮**：主「保留这份」；次「保留为副本（安全）」`secure=true`、「丢弃另一份」（危险）；「稍后处理」。
- **校验**：`keep_id` / `drop_id` 必选且不同。
- **文案硬约束**：必须写成「**按块合并**」（ARB 键 `conflictMergeClass*`），**不得暗示语义合并**（05-03 §6.4声明边界）。
- **失败语义**：合并评估期间进程被杀 → 两侧版本都保留（**不删除任何一侧**），下次启动重新评估（05-03 §6.4⑤）。
- **关闭方式**：ESC / 遮罩（视为稍后处理）。

### M8 冲突副本保留策略
- **触发**：M6 的 `conflict` 段 / P2 冲突分节齿轮。
- **标题**：「冲突副本策略」
- **字段**：`keepWindowDays`（默认 7，可配 1–365）、`copyNameTemplate`（默认 `{name}.conflict-{ts}`）、`maxCopiesPerFile`（默认 5，超出**淘汰最旧**并写审计）（05-03 §6.4④）。
- **按钮**：主「保存」（写审计 `sync.policy`）；次「取消」。

### M9 阅后即焚：创建分享
- **触发**：P3「阅后即焚」入口（仅 `CAP_BURN_SHARE` 置位时渲染）。
- **标题**：「创建阅后即焚分享」
- **内容字段**（对应 `opts_json = {ttlSecs, openTimeoutSecs, maxBytes, relayOnly, codeOnly}`）（05-04 §5.7①）：
  - Offer TTL（默认 15 min；**0 = 不自动过期，需用户显式撤销**——选 0 时必须给出警示）。
  - `open_timeout`（默认 60 s，可配 30–300 s，步进建议 30 s）。
  - `maxBytes`、`relayOnly`（仅中继）、`codeOnly`（仅邀请码）。
- **输出区**（`out_json = {burnId, code, room, expiresMs}`）：一次性邀请码 `base32(...)[0..10]` = **16 字符**、同一串的二维码、`expiresMs` 倒计时（05-04 §5.3）。
- **按钮**：主「创建」；「创建并复制邀请码」；次「取消」。
- **禁用条件**：会话处于 `Maintenance` → 创建按钮禁用并提示（返回 `10`）（05-04 §5.5）。
- **失败语义**：`CAP_BURN_SHARE` 未置位（本壳或对端）→ 入口本就不渲染（05-04 §5.5）。
- **关闭方式**：ESC / 遮罩 / 取消（创建后不可回退，关闭仅收起）。

### M10 阅后即焚：保存到…（放弃自动擦除，危险）
- **触发**：S6 / 会话行「保存到…」。
- **标题**：「保存到…（将放弃自动擦除）」
- **内容字段**：目标路径选择器；**必读提示**「已保存的文件不再自动擦除」。
- **按钮**：主「我确认，保存」（危险色）；次「取消」。
- **校验**：**必须二次确认**（05-04 §5.3）；写审计 `burn saved_as`。
- **失败语义**：无路径/不可写 → `3`。

### M11 立即擦除确认（危险）
- **触发**：S6「立即擦除」。
- **标题**：「立即擦除该分享」
- **内容字段**：将被擦除的对象清单：① 临时明文文件 ② `<burn_id>.vse` 容器 ③ 该文件的 FSKey ④ `burn_secret` 与会话密钥（05-04 §5.4）。
- **按钮**：主「立即擦除」（危险）；次「取消」。
- **文案硬约束**：不得写「数据已彻底销毁」；按介质显示「已加密擦除（+ TRIM）」/「已加密擦除」/「仅加密擦除（介质无法判定）」（05-04 §5.4 诚实边界、ADR-015）。

### M12 擦除失败（danger 全屏）
- **触发**：擦除重试 3 次（间隔 1 s / 5 s / 30 s）仍失败 → `EraseFailed`。
- **标题**：「擦除未完成，存在残留」
- **内容字段**：`burnId` 前 8 位 hex、`retries`、失败对象、介质 `eraseClass`。
- **按钮**：主「立即重试」；次「稍后处理（下次启动自动重试）」。
- **语义**：**保留并告警**（danger，全屏）+ 审计 + 下次启动扫描 `burn/` 内超期项重试（05-04 §5.4、§5.5）。

### M13 中继鉴权失败引导
- **触发**：`R5 auth-failed`（token 无效/被吊销）。
- **标题**：「中继认证失败」
- **内容字段**：中继 id/名称、**不显示 token 明文**、说明「同一 token 重试只会重复失败」。
- **按钮**：主「前往设置核对 Token」（跳设置 → 中继）；次「尝试下一个中继」（仅在配置了多个中继时可用，**多中继是用户显式配置的顺序，不静默回退**）（08 §五）。
- **禁用条件**：无其它中继 → 次按钮禁用。

### M14 破坏性指令确认（销毁 / 锁定）
- **触发**：S1 操作 / 危险区。
- **标题**：「发送销毁指令」/「发送锁定指令」
- **内容字段**：目标设备（`target` 必须 == 对端 device_id）、`delay_ms`、TTL（默认 **7 天**；`0` = 不过期，**需二次确认**）、`expires_ms`、对端 `proto_ver`（=1 时提示「该对端版本不支持时效窗口」，标 `legacy_signature=true`）（08 §4.2）。
- **按钮**：主「发送指令」（危险，输入设备名或短码二次确认）；次「取消」。
- **校验**：`issued_ms` 与本机时钟偏差 ≤ 300 s；时钟超前 > 24 h 或 `now + 5 min < ts_ms` → **拒绝并要求显式确认**（防操纵时钟绕过 TTL）（08 §4.3）。
- **文案硬约束**：对旧版本对端必须提示「该对端版本不支持时效窗口」；**不得**因对端旧而拒绝执行（保持销毁的最终一致性）（08 §4.2）。

### M15 解绑设备（危险）
- **触发**：设备行「解绑」。
- **标题**：「解绑该设备」
- **内容字段**：设备名 + 指纹前缀 + 影响说明（该设备将不再是可信对端；离线队列中未投递的 `kind=3` 轮换传播存在时，该对端同步出站被阻塞）（08 §4.2）。
- **按钮**：主「解绑」（危险）；次「取消」。
- **关闭方式**：ESC / 遮罩 / 取消。

### M16 禁用官方公共中继确认
- **触发**：设置 → 中继 → `allowPublicRelay` 关闭。
- **标题**：「停用官方中继」
- **内容字段**：影响说明「客户端将不向官方中继发起任何连接（连握手都不发生），可用路径只剩局域网 / 打洞 / 自建中继；失败时不会静默回退」（08 §3.6）。
- **按钮**：主「确认停用」（危险）；次「取消」。

### M17 策略读取失败提示
- **触发**：`sync_policy_get` 失败。
- **标题**：「策略读取失败」
- **内容字段**：显示「**策略读取失败，使用默认值**」+ 默认值摘要（`enabled: true` + 无过滤，即「默认全同步」）。
- **按钮**：主「知道了」；次「重新加载」。
- **禁止行为**：**不得静默按「全不同步」处理**（05-03 §七 失败语义）。

## 4. 配对流程（完整分步向导）

### 阶段 0：入口（05-03 §三）
四种载体统一汇入同一个「统一配对会话」，随后必须经**双向认证：交换公钥 + 指纹 + 短码人工比对**：

```
载体① 发现（局域网）──┐
载体② 二维码（扫码）──┤            ┌─────────────────────────────┐
载体③ 邀请码（跨网）──┼──▶ 统一配对 ─▶│ 双向认证：交换公钥 + 指纹    │──▶ 登记 peers.enc
载体④ 手动（地址+码）─┘   会话       │ + 短码人工比对（MITM 防线）  │    + 审计
                                     └─────────────────────────────┘
```
- **安全定位必须写在 UI 文案里**：发现**只解决「地址从哪来」**，不构成任何身份证明——同网段不代表可信；**免手填 ≠ 免认证**（05-03 §3.1）。

### Step 1 选择载体（M1）
- 元素：四个载体块；渲染条件见 M1。
- 各载体提供的认证要素（05-03 §3.3 表）：

| 载体 | 提供的信息 | **仍需的认证要素** |
| --- | --- | --- |
| 发现 | 局域网候选地址 + 指纹前缀 | **邀请码 或 扫码 或 短码比对**（三者任一） |
| 二维码 | 载荷 `{"v":1,"did","pk","fp","addr":[…],"exp"}`（base64-url）——一次扫描同时完成带外公钥交换与地址携带 | **短码比对仍保留**（防「扫错码」） |
| 邀请码 | 一次性码（`pair_begin` 生成，带 TTL） | PSK 握手证明持有码 |
| 手动 | 用户输入 `addr` + 码 | 同邀请码 |

### Step 2a 发现路径
- 列表行元素：未配对必须显示「局域网设备 · 指纹 A3:F1…」（`deviceId`/`name` 为 `null`）；`fingerprint` **仅前 8 hex**；`addrs[]` 含 `transport`/`reachable`/`rttMs`（05-03 §3.4）。
- `caps` 能力摘要 4 hex 可展开（只读，不参与信任）。
- 选择后进入 Step 3。

### Step 2b 二维码生成路径（Offer 侧）
- 元素：二维码 + 载荷字段说明 + `exp`；**`exp` 过期 → 提示重新生成**（05-03 §3.5）。
- 说明文案：扫码本身是带外通道，**比对仍保留，防「扫错码」**（05-03 §3.3）。

### Step 2c 扫码路径（Join 侧）
- 元素：取景框；解析失败 → 「未识别，请重新对准」；`exp` 过期 → 「重新生成」；相机帧不落盘/不进剪贴板/不留日志（05-03 §3.5）。

### Step 2d 邀请码路径
- Offer 侧（M2）：显示一次性码 + QR（同一串）+ `{code, fingerprint, deviceId, port}`；TTL 倒计时。
- Join 侧（M3-③）：输入码 → PSK 握手。

### Step 2e 手动路径（兜底）
- Join 侧（M3-④）：`addr` + `code`；UI 应标注「V2.0 中为兜底路径」（05-03 §二 F-04）。

### Step 3 短码核验（M4，强制）
- 元素：**6 位十进制短码**（双端独立计算，补零）；对比说明；120 s 倒计时（`matchCodeExpiresMs` 从 `p2p_discover` 与配对会话 JSON 回传）（05-03 §3.3、§3.4）。
- 校验：人工比对一致才可点「完成配对」；倒计时归零 → 禁用 + 「重新发起」。
- 失败语义：不一致 → 终止 + 清理会话；码错误/过期 → `1` 或 `6`（**分渠道提示**）；对端格式不兼容 → `6`；能力缺口（发现关闭）→ `13`（05-03 §3.3）。

### Step 4 完成与登记
- 成功 → 写 `peers.enc`（`HKDF(MK,"p2p-peers")`）+ 审计 `p2p.pair`（detail：`peer_id`、载体类型、指纹前缀）（05-03 §3.3、§8.1）。
- UI：设备进入已配对列表（此时才显示名称，来自 `peers.enc`）；提示可「立即同步」。

### Step 5 首次同步（P8 阶段 DoD）
- 端到端判据：**两台干净设备在无手填地址下完成首次同步**（发现 → 配对（短码比对一致）→ 首次全量 → 条目数一致）（05-03 §6 测试矩阵第 1 行、§8.2）。

### 5.2 传输队列分节
- **结构**：单队列 + 三档优先级：`destroy`（销毁/远程锁定指令）> `interactive`（配对/分享/阅后即焚）> `background`（同步/导入/导出/压实）（05-03 §5.2）。
- **任务行字段**（建议列）：`task_id`（引擎分配 u32，进程内单调递增不复用，**UI 关联队列行的唯一键**）、文件名、方向（上行/下行）、对端、优先级、状态、进度（已传/总量、块数、速率、ETA）、`resumable`、路径类型（Direct/Punched/Relayed）（05-03 §5.2、§5.3、§4.4）。
- **状态枚举**：`queued` / `transferring` / `paused` / `interrupted` / `cancelled` / `completed` / `failed`；**对端离线 → 任务入队但状态 `queued`，不报错**（等对端上线）（05-03 §5.2 失败语义）。
- **行内操作**：⏸ 暂停 / ▶ 恢复 / ✕ 取消 /「详情」（05-03 §5.4）。
- **抢占呈现**：`destroy` 直插队首并**可抢占 `background` 的连接**（**不中断已提交的块**）；`interactive` **不抢占**，只在管道空闲时先取（05-03 §5.2）。
- **逐块进度**：按 `(task_id)` 合并 + 100 ms/任务 节流；前端渲染节流 **33 ms**，丢弃回退值，**不重复做逐块限流**；`TASK_PROGRESS` 帧可丢弃；**逐块进度永不发系统通知**（静默项）（05-03 §5.3）。
- **入队去重**：同一 `file_id` 的重复请求合并为一个任务（更新目标）；`destroy` 类**不去重**（可对多设备并发）（05-03 §5.2）。
- **失败语义**：队列满 → `7`；未知 `task_id` → `7`；对端未配对 → `7`；只读降级 / 维护态 → `9` / `10`（05-03 §5.2）。

### 5.3 单文件同步详情（S3）
- **块进度面板**：`doneChunks/totalChunks`、`doneBytes/totalBytes`、`rateBps`、`etaMs`、`resumable`（05-03 §5.3）。
- **跨会话续传面板**：
  - 显示「**续传 x%（跨会话）**」，用户点「继续」即从索引表续收（05-03 §6.2）。
  - 版本判据说明：`.part` 头部含 `file_sha256`（对端清单的整文件哈希）——**对端文件已变（哈希不同）时一律作废重传**，绝不把两个版本块拼成一个文件（**安全优先于带宽**）（05-03 §6.1）。
  - 启动恢复扫描六情形的用户可见结果（05-03 §6.2）：

| 情形 | UI 呈现 |
| --- | --- |
| `magic` / `header_crc32` 失败 | 文件被删除 + `ERROR_DIAG`（**不猜测、不尝试修补**），UI 显示诊断条目 |
| `file_id` 不存在 / 配对记录已删 | 残留删除（用户不可见或仅在诊断页） |
| `file_sha256` 与索引不一致 | **作废重传**，原因 `version_changed`（`ERROR_DIAG`） |
| 头部合法且版本一致 | 登记为 `interrupted` + `resumable=true`，「续传 x%（跨会话）」 |
| 总占用超限 | `.part` 合计 ≤ `max(5 GiB, 库大小 × 20%)`；超限按「最久未续」淘汰并记 `ERROR_DIAG` |
| 龄期超限 | 30 天未续 → 清理 |

- **失败语义**：索引表 `index_len` 与实际块数不符 → 视为头部损坏（删除）；`.part` 所在卷不可写 → `3` 且**不进入队列**（避免留下半成品）（05-03 §6.2）。
- **操作按钮**：「暂停」「恢复」「取消」「仍要同步」（被策略拦下时）（05-03 §5.4、§5.5、§七）。
- **取消语义呈现**：取消 → 状态 `cancelled`（码 **12**，**视为正常结果**，UI 不用红色错误态）→ 资源 **5 s 内**释放；`.part` **保留**（可续传），除非 `opts.discard_partial = true`（05-03 §5.4）。
- **暂停语义呈现**：协作式停在**块边界**，状态 `paused`，**保留队列位次与管道**（管道空闲超 60 s 释放但保留位次）（05-03 §5.4）。
- **锁定触发**：与取消同路，`reason = lock`（三值 `user/system/lock` 之一）；UI 文案应区分「你取消了」与「系统锁定导致暂停」（05-03 §5.4、§8.1）。

### 5.4 冲突解决（S4 / M7）
- **固定优先级（V1.0 沿用，语义不变）**（05-03 §6.3）：
  1. **删除优先于版本保留**；但删除方在保护窗口期内（`PROTECT_WINDOW_MS = 24 h`）**先留加密冲突副本再删**。
  2. 无删除时**保留多版本**：副本命名 `{name}.conflict-{ts}`。
  3. **向量时钟**识别因果关系、减少虚假冲突（**不直接裁决**）。
- **原地编辑与块级三方合并**（05-03 §6.4）：
  - 用户用本地编辑器改完的文件作为**同一 `file_id` 的新版本**提交（`opts_json = {keepRevs, extractTokens, ttlDays}`；`keepRevs` 默认 1，即只留上一版）。
  - 评估三态：

| UI 呈现 | 触发 | `mergeClass` | 说明 |
| --- | --- | --- | --- |
| 「已按块自动合并」 | 两侧改动块集合**不相交** | `auto` | 合并为 `rev+1`，`conflictFree = true` |
| 「存在冲突，请选择保留」 | 任一块被两侧**同时改动** | `conflict` | 生成冲突副本，`ConflictPair`（`color.quarantine`）供保留/丢弃 |
| 「已作为新版本替换」 | 无法比较（大小差异超阈值 / 缺基线） | `replace` | **如实呈现，不假装合并成功** |

- **文案硬约束**：这是**块级**合并，不是文本/Office 语义合并；UI 必须写成「**按块合并**」（ARB 键 `conflictMergeClass*`），**不得暗示语义合并**（05-03 §6.4 声明边界）。
- **失败语义**：`src` 不可读 → `3`；维护态/只读 → `10`/`9`；磁盘不足 → `3` 且**旧 rev 完整保留**；合并评估期间进程被杀 → **两侧版本都保留（不删除任何一侧）**，下次启动重新评估（05-03 §6.4⑤）。

### 5.5 冲突副本保留（M8）

## 6. 通信界面（P3）

### 6.1 会话列表
- **会话类型严格区分（UI 文案硬约束）**（05-04 §5.1）：

| 通道 | 软件行为 | **用户可见名称** |
| --- | --- | --- |
| 受限次数分享（V1.0 现状，`share_create`/`share_open`） | 本地令牌 `HMAC(令牌)` + TTL + 次数上限，**本机导出明文到 `dest`** | 一律称「**限次导出**」；导出后必须明示「**已导出，不再自动擦除**」 |
| 阅后即焚（V2.0，`share_burn_create`/`_status`） | 一次性 P2P 会话 + 对端打开后/超时自动加密擦除 + 明文不留存 | 只有 `CAP_BURN_SHARE`(13) 置位且走 burn 通道的才叫「**阅后即焚**」 |

- **行字段**：会话 id（`burnId` 前 8 位 hex）、对端指纹前缀（`peerFingerprintPrefix`）、`phase`、`bytes`、创建时间、`expiresMs` 倒计时、`consumed` 标记（05-04 §5.7①②）。
- **入口渲染**：`CAP_BURN_SHARE` 未置位 → **整个阅后即焚入口不渲染**（不置灰、不写「即将推出」）（05-04 §5.5）。

### 6.2 消息/任务线程
- burn 的进度**复用队列行**（`QueueRow` / `TransferRing` 消费 `TASK_*` 事件）（05-04 §六）。
- 事件映射（05-04 §4.6、08 §4.7）：

| 语义 | 事件 | 载荷要点 |
| --- | --- | --- |
| 会话/信道就绪 | 1 `ENGINE_READY` | `mode`、`recoveryReport` |
| 路径与档位变化 | 12 `PEER_STATE` / 13 `PATH_DEGRADED` | `peerId`、`state`、`channelType`；`reason` |
| 同步任务进度 | 7 `TASK_PROGRESS` | `doneBytes/totalBytes`、`doneChunks/totalChunks`、`rateBps`（线上字节） |
| 传输完成/失败/取消 | 8 / 9 / 10 | `resultJson`；`errCode`；`reason ∈ user/system/lock` |
| 审计条目产生 | 20 `AUDIT_APPENDED` | `seq`、`headHash`（**不含 detail**） |
| 信令异常诊断 | 22 `ERROR_DIAG` | `component ∈ vault-net|vault-p2p|vault-audit`、`message` 结构化枚举 |
| 中继会话被关闭（R10–R12） | 9 `TASK_FAILED` / 任务 `interrupted` | `errCode=13`、可读 `diagnostic`、`resumable=true` |
| 破坏性指令投递与执行 | 8 / 9 | 已投递/已执行/被拒（含 `legacy_signature` 标记） |

- **纪律**：引擎**不产生用户可见字符串**；上述 `reason`/`component` 均为枚举，**前端映射 ARB 键**（05-04 §4.6）。

### 6.3 阅后即焚状态机在 UI 上的呈现（11 态）
（05-04 §5.2、§5.5）

| 阶段 | 含义 | UI 建议 |
| --- | --- | --- |
| `Idle` | 未创建 | — |
| `Offering` | 已创建、等待对端加入；Offer TTL 默认 **15 min**（0 = 不自动过期，需显式撤销） | 倒计时 + 「撤销分享」+ 邀请码/二维码 |
| `Joined` | 对端持票入场（票据单次有效，消费一次） | 「对方已加入」 |
| `Transferring` | 传块中 | 队列行进度复用；`resumable`（**同会话内**） |
| `Delivered` | 全部块 + 整文件 SHA-256 终验 + 对端 `BurnAck(delivered)` | 发送端票据作废、会话密钥 Zeroize、本地发送缓存（若有）擦除；`consumed=true` |
| `Opened` | 接收端状态，发送端经单向 `BurnAck(opened)` 得知（**只回传阶段枚举，不含任何明文或文件名**） | 「对方已打开」；60 s 倒计时 |
| `Erasing` | 打开后 / 超时 / 用户关闭文件 / 显式「立即擦除」 | 显示擦除进度与 `eraseClass` |
| `Erased`（终态） | 票据、会话密钥、容器、临时明文均不存在 | 终态徽标 |
| `Rejected` / `Expired` | 对端拒绝、票据错误、重复使用票据 | 「**对方未接受，分享已撤销**」（码 `12`，**视为正常结果，不报错**） |
| `EraseFailed` | 重试 3 次仍失败 | **danger 全屏告警 + 保留 + 下次启动重试**（M12） |

- **关键性质提示文案**：`Delivered` 之后**票据不可复用**（`Erased` 与 `Delivered` 共享「票据已消费」状态）（05-04 §5.2）。
- **网络中断（`Transferring` 中）**：保留已收块（**允许续传**）；Offer TTL 内可重连；超 TTL → `Expired` 并擦除；事件 9 `TASK_FAILED` + `errors=3`，`resumable=true`（05-04 §5.5）。
- **续传边界（必须明示）**：burn 允许**传输层**续传（块幂等），但**不允许跨会话恢复**——`burn_secret` 不落盘，进程重启即无票据 → 未完成的 burn 一律收敛为 `Expired`（接收端未收完的容器一并擦除）（05-04 §5.5）。
- **维护态**：创建新分享 → `10`（写冻结）；**已在进行中的 burn 会话允许完成**（擦除语义优先，且 burn 不经保险箱索引）（05-04 §5.5）。

```
                                                        ▼                              │
                                              ┌────────────────────┐  打洞成功（≤5 s）  │ RTT 超阈值 /
                                              │      Punching      │───────────────────┘ 连续重传
                                              └─────────┬──────────┘                      │
                                 对称 NAT 判定 / 打洞超时  │                              │
                                                        ▼                                │
                                              ┌────────────────────┐  每 5 min 尝试升级   │
                                              │      Relayed       │◀─────────────────────┘
                                              └────────────────────┘
   每次迁移：发 PEER_STATE(12)（新路径）与路径变化时的 PATH_DEGRADED(13)（**带原因**）
```

- **迁移规则与 UI 呈现**（05-03 §4.2）：

| 迁移 | 触发 | UI |
| --- | --- | --- |
| `Direct → Relayed` | 连接中断且重建直连失败 2 次 | 降级（**不是失败**）；任务状态 `Interrupted`，网络恢复后自动续传；**不得用红色「失败」态** |
| `Punched → Relayed` | 打洞路径连续 30 s 无有效帧 | 降级并显示原因 |
| `Relayed → Punching/Direct` | 每 5 min 一次**空闲窗口**内的升级尝试 | 只在无活跃大任务时尝试；显示「正在尝试直连」 |
| 任一路径不可用 | 中继 `RelayLimit` 控制帧 / 中继不可达 | 先降级重试一次；仍失败 → `TASK_FAILED` + 可读原因 |

- **降级原因枚举与建议文案**（05-03 §4.2 + 08 §4.5 新增 `proto_downgrade`）：

| reason | 建议文案 |
| --- | --- |
| `direct_timeout` | 「直连超时，已切换到打洞」 |
| `hole_punch_timeout` | 「打洞超时，已回退到中继」 |
| `symmetric_nat` | 「检测到对称 NAT，无法打洞，已回退到中继」 |
| `relay_limit` | 「中继达到限额（时长/空闲/字节），已尝试直连」 |
| `relay_unavailable` | 「中继不可用，已尝试其它路径」 |
| `padding_downgrade` | 「填充档位已降级（协商结果/对端版本）」 |
| `proto_downgrade` | 「协议版本已降级到 v1（对端为旧版本）」 |

- **「失败可诊断」的落地**：任何降级都必须带 `reason`，原因进 `PATH_DEGRADED` 事件与 `vault_core_p2p_path_status`；**前端在设备行展开一行说明，3 s 自动收起**（动效 #10）（05-03 §4.2）。
- **`path_status` 全字段（可观测面）**（05-03 §4.4②）：
  `{ schema, peers[{ peerId, path: "direct|hole_punch|relay", pathSinceMs, attempts{direct,punch,relay}, candidates{local,remote,relayObserved}, lastFailure{reason,atMs}, relay{id, sessionTtlMs, rateLimited}, bytesIn, bytesOut, rttMs, paddingTier }] }`
  - `padding` 诊断子对象（只增字段）：`{ padTier, floorBreached, legacyPeer, overheadRatio, frameLenHistogram }`（05-04 §3.6①、08 §六测试组 7③）。
  - `proto` 子对象：`legacyPeer`（08 §4.5）。
  - **隐私纪律**：只给候选数量与类型，**不给 IP/端口明文**；诊断包导出时对地址做哈希前缀处理（05-03 §4.4③）。
- **失败语义**：`CAP_DISCOVERY` / `CAP_HOLE_PUNCH` 未置位时对应字段缺省（`null`）而非报错；无对端时 `peers: []`（05-03 §4.4④）。
- **中继选择 UI**（08 §3.6、§五）：多中继按**用户配置顺序**依次尝试；不静默回退；`R5` 后引导设置页；`R6/R7` 自动重连 1 次；`R10/R11/R12` 降级为直连重试一次；`R14/R15` 换中继或直连。
- **中继会话上限的可见性**：`relay.sessionTtlMs` 倒计时；`rateLimited=true` 显示「中继限速中（只降速，不丢字节）」；`closeReason` 展示 `{peer, idle, time, bytes, frame, error, shutdown}` 的本地化文案（08 §3.5、§3.7）。

### 6.6 通话/文件传输
- **本三份文档未定义"通话"（语音/视频）能力**。文档范围内的"通信"仅包含：① Noise 信道上的同步/信令；② 一次性的 burn 文件分享通道（05-04 §一、§五）。
- **文件传输的 UI 面** = 队列行 + burn 会话详情（见 §5.2、§6.3）。
- ⚠️ 若原型需要"通话"界面，本三份文档**不提供依据**，须另行取得设计输入。

**另外必须呈现的中继侧状态**：
- `close_reason` 枚举：`{peer, idle, time, bytes, frame, error, shutdown}` —— 建议文案依次为「对端断开」「空闲回收」「时长到期」「流量用尽」「协议错误」「内部错误」「服务停止」（08 §3.5）。

## 8. 文案要求

### 8.1 必须出现的提示语（逐条为文档明文要求）
1. 「**局域网发现不可用**」——mDNS 绑定失败时；**不得**显示「未发现设备」（05-03 §3.4④）。
2. 「**免手填 ≠ 免认证**」/「发现只解决『地址从哪来』，不构成任何身份证明；同网段不代表可信」（05-03 §3.1）。
3. 「局域网设备 · 指纹 A3:F1…」——未配对设备的固定呈现格式（05-03 §3.1）。
4. 「**按块合并**」——冲突合并文案，ARB 键 `conflictMergeClass*`；**不得暗示语义合并**（05-03 §6.4 声明边界）。
5. 「**已导出，不再自动擦除**」——限次导出通道的结果提示（05-04 §5.1）。
6. 「**已保存的文件不再自动擦除**」——burn「保存到…」的二次确认文案（05-04 §5.3）。
7. 「**对方未接受，分享已撤销**」——对端拒绝/票据错误/重复使用（05-04 §5.5）。
8. 「**已加密擦除（+ TRIM）**」/「已加密擦除」/「**仅加密擦除**」——按介质强度如实显示；**不得**写「数据已彻底销毁」（05-04 §5.4 诚实边界、ADR-015）。
9. 「**策略读取失败，使用默认值**」（05-03 §七、M17）。
10. 「**该对端版本不支持时效窗口**」——对 `proto_ver = 1` 对端签发破坏性指令时（08 §4.2）。
11. 「**中继正在限速：传输会变慢，不会丢数据**」（08 §3.3 纪律 2 + §4.7）。
12. 「**续传 x%（跨会话）**」——启动恢复扫描命中合法 `.part` 时（05-03 §6.2）。
13. 「**填充档位已降级**」类说明 + `floorBreached` / `legacyPeer` 诊断字段（05-04 §3.3、§3.6）。
14. 「**协议版本已降级**」+ `proto.legacyPeer`（08 §4.5 规则 3：**降级必须可见**）。
15. 填充的**诚实边界**必须写入文案：只掩盖「精确长度 + 消息边界模式」→ 降级为「总长的 64 KiB 量化值」；**不构成抗流量分析信道**；不做恒定速率整形；不做压缩（05-04 §3.4）。
16. 「**任何降级都不得静默**」的落地：每次迁移都发 `PEER_STATE` / `PATH_DEGRADED` 并**带原因**，设备行展开一行说明（3 s 自动收起）（08 §五、05-03 §4.2）。
17. 「**审计写入异常，操作已完成**」类提示（审计失败不阻断业务，但必须发 `ERROR_DIAG`）（05-04 §4.5）。
18. 「**该信道已被标记为不可信**」（05-04 §4.4、08 §4.1）。
19. 相机隐私说明：帧**不落盘、不进剪贴板、不留日志**（05-03 §3.5）。
20. 官方公共 token 的定位说明：它是**公开凭据**，**不提供身份保证**（08 §3.2）。

### 8.3 文案纪律（非文案内容本身，但影响实现）
- **引擎不产生用户可见字符串**：`reason` / `component` 均为枚举，前端映射 ARB 键（05-04 §4.6、08 §4.7）。
- **不得把中继错误码直接呈现给用户**（08 §3.7③）。
- **不得出现「即将推出」**用于能力位缺失的功能（05-04 §5.5、05-03 §3.5）。
- **不得谎报**：不谎报「无设备」（05-03 §3.4④）、不谎报「已彻底销毁」（05-04 §5.4）、不谎报「已填充」（05-04 §7.1）。
- **审计脱敏**：审计 detail 只写票据 id 前 8 位 hex，不写 `burn_secret`、不写文件名、不写对端地址（05-04 §5.6）；`sync.policy` 审计只写变更字段名，**不含过滤值明细**（值里可能含文件夹名）（05-03 §8.1）。
- **界面不展示对端地址与端口**（05-03 §4.4③）。
