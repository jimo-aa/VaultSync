## 〇、先说三条**必须先知道的诚实结论**（避免原型做出文档没有的界面）

这三条是「不存在的界面」，必须在原型中明确**不做**或**明确留白**，否则会造出文档未定义的假需求：

1. **不存在商业「订单」界面。** 文档 `12` **全文未出现**购物车、下单、支付、结算、订单列表、订单详情、退款等任何界面定义。`12` §1.3 把「定价数字、支付渠道、经营主体与税务、退款政策、许可协议（EULA）法务条款」**明确列为非范围**；§10.3 把「经营主体、支付渠道、税务与退款政策」列为**阻塞 P9-11d 的业务方前置决策**。
   ⚠️ **易混淆点**：`12` §7.1 的从属密钥 `key_id=4`（订单密钥）、`09` P7-4 的 `orders.enc`、`OrderRec.kind`（`1 = 销毁` / `2 = 锁定` / `3 = 轮换传播`）**是跨设备指令信封，不是商业订单**。原型里任何「订单」页面只能指这两者之一，不得虚构商业订单流。

2. **不存在试用期。** `12` §6.3「必须避开的四个坑」第 3 条明确反对「把免费版做成试用版（**有期限**、有水印、功能倒计时）」——理由是「加密保险箱加限制会让人觉得数据不安全，直接反噬核心价值」。因此**不得**设计「试用 14 天」「试用到期」类界面。

3. **不存在发票 / 收据界面。** 属 `12` §1.3 非范围（税务）+ §10.3 第 5 项（支付渠道、税务与退款政策）业务前置。原型只能留「由业务方补齐」的接口位。

此外：**`12` 不给任何具体价目**（§1.3、§6.2 明确「本文档不给具体价目」「不引用任何具体价格」），所以套餐对比表**价格列必须是可配置占位**，不得硬编码数字。

### 1.5 支付方式选项

- **文档未定义任何支付方式**。`12` §1.3 把「支付渠道」列入非范围；§10.3 第 5 项把「经营主体、支付渠道、税务与退款政策」列为**阻塞 P9-11d 的业务方前置决策**。
- 因此原型中**不得**出现信用卡/支付宝/微信/PayPal 等具体支付控件。若必须占位，只能做成「由业务方补齐」的空态，且在页面内注明出处（`12` §1.3 / §10.3）。
- 与支付最接近的**唯一**交互是 **A4 中继额度兑换**（`12` §7.3），它是一次 https POST 到「**用户可见的域名，非隐藏端点**」——这一句是 UI 要求：域名必须可见，不得使用隐藏端点。

### 1.6 「订单」状态机与状态文案

商业订单状态机**不存在**（见 §〇 结论 1）。以下是文档中**真实存在的三个状态机**，原型必须分别呈现、**不得混为一体**：

**（1）中继额度兑换状态机**（`12` §7.3，唯一一次联网）

| 状态 | 触发 | 用户可见文案要点 | 错误码 |
| --- | --- | --- | --- |
| 空闲 | — | 「兑换中继额度」按钮（用户主动触发） | — |
| 构建请求 | 点击 | 调 `vault_core_license_redeem_build` → 得到请求 JSON（含许可证 + 挑战 nonce） | 构建失败（无许可证 / 许可证过期）→ **14** |
| 传输中 | Dart https POST | 到授权服务（**用户可见的域名**） | 网络失败 → Dart 侧 **3**（IO），**保留上次有效 token** |
| 服务端签发 | 验签许可证 → 按 tier 与额度策略签发 relay token（Ed25519 签名） | — | — |
| 离线验签落盘 | 调 `vault_core_license_redeem_finish(response)` | — | 验签失败 → **6**，**保留上次有效 token** |
| 生效 | 之后每次连官方中继 | token 作为 `VSR2` 的 token 参与 proof 计算 | — |

**状态文案硬约束**（`12` §7.5）：**14 与 13 必须严格区分**——「混用这两个码会导致『隐藏了可升级的功能』或『给不存在的功能显示升级按钮』」。
**能力位**：`CAP_LICENSE`（**bit 19**）= 引擎具备许可证门禁与离线验签能力；未置位时**不渲染任何授权 UI**，调用授权 API 返回 **13**（`12` §7.5、§8.3）。
**事件**：授权**状态**变化通过事件 **`LICENSE_CHANGED`(24)** 通知前端，载荷 `{tier, features[], expiresMs, licenseId}`，**不可丢弃**；前端据此重算档位（`12` §8.3）。
> `CAP_LICENSE` 与 `CAP_SECURE_STORE` / `CAP_BIO` 一类**运行期可变位不同**，它描述**构建能力**，因此**运行期不变**，只在 ABI 握手时读一次（`12` §8.3）。

### 2.4 差异化定位中**最重要的 UI 冲突**：否认性 × 同步 × 审计（`13` §4.5）

这是 `13` 明确标注的「**本文最重要的一条结论**」，直接决定原型结构：

- **三方拉扯**：否认性要求「任何证据都不得暗示真空间存在」；同步要求「多设备副本、设备清单、配对记录」；审计要求「一切发生过的都要留下可验证痕迹」。
- **共享的证据**：`peers.enc` / `audit.enc` / `orders.enc` 的存在本身，以及「真空间密文副本躺在多台设备上」，都在削弱伪装空间的可否认性。
- **最尖锐的一点是可检验的**：`05-01` §三.1 要求伪装空间与真空间「结构与行为上无法区分」。于是：
  - 若伪装空间**有**自己的 `peers.enc` / `audit.enc` / `orders.enc` ⇒ 会把「真空间存在过」变成可推断的；
  - 若伪装空间**没有**这些文件 ⇒ **目录树的结构差异本身就泄露了真相**，直接违反该设计要求。
- **原型的对应硬要求（建议已登记 `11`，需固化为可测试性质）**：
  - 断言「伪空间与真空间的 `data_dir` 文件集合**逐一对应（含空占位文件）**」；
  - 断言「两者在**配对数 / 审计条目数 / 订单队列**上的表现**不可区分**」；
  - 明确「**伪空间不得出现授权 / 付费 UI**」（与 `12` §7.1 一致）。
- ⇒ **UI 后果**：伪装空间页面的**信息架构必须与真空间一致**（含空占位行/空态），不能因为「伪空间里没有配对」就少渲染整块区域。授权/付费/档位相关 UI 在伪空间**整体缺席**（不是置灰）。

### 2.5 「只存不解」节点角色 = 当前最明显的架构空白（`13` §三、§五 候选 #1）

| 轴 | Syncthing untrusted | VaultSync | 判定 |
| --- | --- | --- | --- |
| 密钥来源 | folder key = `scrypt(password, folderID)` | MK 由 CSPRNG 生成，密码 / 生物识别只是包装它的 KEK | **VaultSync 优**：改密码**零重加密** |
| 文件名保护 | AES-SIV + base32 | 加密元数据整体 AEAD | 同级 |
| 块加密 nonce | XChaCha20-Poly1305 + 随机 192 位 nonce | AES-GCM + 确定性 `前缀(32)‖计数器(64)` | 两者均可辩护，但本项目的选择依赖「永不重用」纪律 |
| 跨文件块复用 | 明确禁止 | 靠 per-file FSKey 达到类似效果 | 殊途同归 |
| 可观测元数据 | 文件大小、哪部分变了、何时变 | 文件大小、CDC 边界、同步时序 | 同级（双方都如实声明为降级项） |
| **能否使用「只存不解」的节点** | ✅ 可以 | ❌ **不能**（每个已配对设备都持 MK） | **Syncthing 领先 —— 本项目最明显的架构空白** |

- ⇒ **UI 后果（关键）**：该能力**当前不存在**，且 `13` §五 明文规定候选方向「**在补齐四项要素之前，不得进入 `09` 的完成标准**」，`09` §七·补 亦标注「**未立项，不占任务号、不得勾选**」。
  **因此原型中不得出现「只存不解节点」的可操作 UI**（顶多作为「候选 / 计划中」的只读说明，且必须标明未立项）。
- 若将来引入：**必须如实声明同样的降级**——「大小与变化模式可见」（文件大小与「哪部分何时变化」可见）（`13` §3.1）。

## 六、给原型实现的硬约束速查（一句话版）

1. **不做商业订单、不做支付方式、不做发票收据、不做试用期**——文档未定义（`12` §1.3 / §6.3 / §10.3）。
2. **价格列一律可配置占位**，不得硬编码（`12` §6.2）。
3. **Free-forever 十项在任何界面不得标为「Pro 功能 / 需升级」**（`12` §3）。
4. **伪装空间：授权/付费 UI 组件数为 0**，且**信息架构与真空间逐一对应（含空占位）**（`12` §7.1、`13` §4.5）。
5. **13 隐藏、14 置灰+升级引导**，不得混用（`12` §7.5）。
6. **无许可证 = `tier:"free"` = 正常状态**，不是错误（`12` §7.6）。
7. **许可证导入失败保留原许可证**；**许可证丢失/损坏重新导入即可**；**四种授权状态下七项本地操作全部正常**（`12` §7.6、§9）。
8. **UI 不得声称「无法破解」**、不得声称有匿名、不得把同步说成备份、不得说像普通文件夹、不得混淆「改密码」与「轮换主密钥」（`12` §7.8、`13` §六、§4.7）。
9. **UI 不得自算隐写容量**（`vault_core_stego_plan` 唯一真值）（`09` P8-10）。
10. **UI 不渲染异地检测开关**（V2.0 明确不做）（`09` P7-10）。
11. **「安全擦除」字样条件性出现**，否则如实降级（`09` P7-5）。
12. **未完成任务不得渲染为可用功能**；「已完成」必须能对应 `11` 的判定列（`09` §一、§九.5）。
13. **二级界面一律 modal，不用抽屉**；纯静态零依赖 HTML/CSS/JS（`AGENTS.md`）。
